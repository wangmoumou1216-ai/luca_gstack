采用、stage、run、recover 分开：用户已选工具/模块不证明最终 bundle 采用或外部写入授权；各授权/能力/状态均未核。没有本轮 OD 接收/read-back/生成/recover 证据；导出/置入不叫生成完成。
冻结/绑定顺序：补关键源/状态/范围证据 → 审核正文到单一 Packet 的全量语义 → 按真实字节冻结 → 实际源适配与全量 TAC 投影 → 独立真人采用 → 分项操作。未指定且明确无模板才可选择 reference_only；本轮指定源不可藉此跳过冲突。
structural_carrier 不继承视觉；visual_carrier 需真实 viewport/基线/差异阈值，当前均无；不宣称模板视觉保真。
工程消费者：实际 PRD/工程门禁仍独立必需；设计源完整登记不授予 tech-spec/task-plan/development readiness。
执行 profile S（结构，候选，未验证）：只能选择实际允许的 add 或 modify 加 preserve；对应 D-F8-01/02/03/05/06。准确动作、索引、受限片段能否保真交互尚未核；profile S 不含 refine。
执行 profile R（精修，候选，未验证）：结构阶段通过后以其实际输出版本形成新基线，仅 refine + preserve（original-ui-refinement-v1 的实际适用性待核）；对应 D-F8-04/06 并继续执行全部保持事实。profile R 不含 add/modify。两者分开组包、版本/动作核验、采用和执行授权；现有选择无需无端重问，但不假造新 bundle 采用。
若 original_copy 的受限静态片段不能承载原搜索/详情/返回等行为，报告具体能力 BLOCKED，保留植入 MUST 与完整行为，不把结构简化或一次混合修改当达成。
