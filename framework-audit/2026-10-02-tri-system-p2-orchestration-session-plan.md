## 零、所有后续 Session 必须继承的背景


**luca_gstack 是在 Codex 桌面、Codex CLI、Claude Code CLI 中通用使用的一个框架。评估按三体系及其协同作用组织，最终产出一份统一的评估执行计划。** 本文将用户口述的“Cloud Code”按 Claude Code 理解；该名称不改变通用框架这一评估对象。

用户本次明确要求：“按照它们的通用价值，然后去考虑我的框架上面的这几大模块的问题以及计划的输出。”据此，以下约束适用于目的整理、研究、独立规划、设计、审计、比较、裁决和迁移：

- **以共同用途定义价值。** 从理解任务、组织执行、保持信息连续性和必要的人类控制出发，研究框架在当前模型与实际运行环境能力之上增加了什么价值；这些价值是否值得其规则、协调和维护成本。
- **保持一个框架的规划对象。** 不按三个使用端拆成三套方案、三组模块或平台专项 Session，不预设需要新增适配层、平台分支或配置体系。若证据表明统一目标存在无法消除的能力冲突，记录影响并回到共同用途裁决，不由执行者自行扩大架构。
- **区分能力事实与架构选择。** 模型本身的能力、环境实际提供的执行能力、框架增加的机制，分别作为归因依据。环境名称不充当方案分组依据；必要的能力核实服务于同一方案的可行性判断。
- **通用性不等于采用最弱能力。** 不要求实现方式完全相同，也不凭空假设各处都有同一能力。无法取得必要能力时，先检验现有能力能否以更简单方式达到同一结果；仍不能满足必要控制或用途时明确限制，不静默削弱目标。特有增强的收益不能冒充通用收益。
- **以证据控制复杂度。** 每个保留或新增机制都要说明服务的共同用途、必要能力前提、最小替代及净价值。确需核实环境差异时，只检查可能改变结论的行为与控制点，复用同一任务和判据；不得以此自动扩成全端、全组合的独立评估工程。
- **按模块职责限定范围。** 三体系评估负责通用的任务分流、Agent 协作、Context 提供及其交接；技能内部领域方法、动效或其他具体交付流程仍由技能 owner 负责。技能作为真实任务的消费方或案例时，只检查与三体系有关的输入、输出和控制衔接。发现技能内部问题，记录具体责任边界，不自动扩大为技能重构或新增评估模块。
- **允许高价值交集优先进入。** 主协调者可将直接改善共同用途或评估可信度、且能保留最新提交有效行为的交集列为优先项。先复用现有 owner；确有额外收益才设计最小增补实验，并记录收益依据、责任边界和回归要求。优先项使用既有任务卡，不新增阶段或审批体系，也不扩大实施授权。

本节是共同输入合同，必须随最小任务包和跨 Session 交接传递。执行者不能只读某一阶段而丢失本节约束。

## 二、问题与评估深度

〔共／冷〕问题是额外执行者、等预算顺序尝试、并行分工及独立审查何时改善可消费结果，净收益是否超过通信、等待、合并、重试、维护与恢复成本。S2/S7 支持排除额外计算解释，S4 支持结果与轨迹分开验证，S8 提供故障编码；均不证明本地收益。

| 深度 | 可决定什么 | 边界与升级条件 |
|---|---|---|
| 静态审计 | 重建用途、依赖、责任、缺失出口和可疑重复 | 不能证明遵循、成本或质量；实际收益与恢复必须有行为证据 |
| 定向局部实验 | 完整链路已有疑点后区分分工、采样、审查与自检 | 不推整个框架收益；影响选路、信息或最终交付则回整链 |
| 独立设计＋行为比较 | 可执行替代在同任务、同资源内的净价值 | 不为凑数造四套系统；等价合并／不可行排除留依据 |

〔补〕最小替代是原生能力＋必要提示与资料，保留同样目标、权限、验收和事实入口。若已满足用途且无额外收益证据，可停止增复杂度；若不能公平重置、隔离宿主改写或核验结果，暂停相应因果判断，不自动改造生产环境。当前规划不设候选默认架构。

## 四、跨模块接口与失败判据

〔冷〕路由提供任务目标、授权约束、歧义澄清、所选处理和依据；编排返回执行可行性、责任、依赖、预算需求和失败。路由负责选择为何合适，编排负责选择后的组织价值；不因多人参与重复归功。

Context 提供同源事实入口、最新更正、证据状态、决定与恢复信息；编排记录各执行者实际获得／消费什么、冲突如何合并、未完工作与恢复需求。Context 负责信息可得，编排负责消费和合并，各自留证。领域技能提供成品与专业验证，最终合并责任由编排明确，不能扩大到技能内部重构。

越权、已知失败或过期结果继续下传、合并丢必要内容、子任务失败却宣称完成、恢复忘记更正导致错误行动、无人对最终交付负责，均为整链失败。归因记录最早可证偏离＋后续放大因素：未提供、未消费、错误合并分开；不足则未归因。〔补〕技术能力前提必须中性核实，不能把旧职责或层级重新包装为设计侧硬条件。

## 五、样本、消融与共同预算

〔共／冷〕B=当前体系，T=原生能力＋最薄必要提示／资料，S=针对性精简，I=目标导向独立候选。6用途层各1开发＋2隐藏例，最多4条件：开发6×4×1=24，隐藏12×4×2=96，基础120；所有模块合计额外24，合计144。条件合并可减少。层非互斥、不表示频率。12隐藏例交叉含至少2可分解、2强依赖、2不值额外分工、2固定点恢复，标签可重叠；覆盖错误传播、过期决定、假完成。两重复仅描述，不承诺统计显著或低失败率。

本模块仅两种条件性消融〔冷；补公平规则〕：

1. 分工差异或额外采样解释未排除时：一可分解、一强依赖任务，并行组织对等预算单执行者顺序尝试，2题×2条件×1=4run。顺序可重试并按预注册方式选优／合并，不能靠评分真值挑最好；分派、尝试、选优、合并、验证全计资源，不能让并行获额外合并者预算。区分墙钟收益与质量收益。
2. 审查发现关键错或重复验证疑点时：2题×独立审查／原执行者自检=4run。用冻结同一待检产物、事实和目标，完成修复与终态核验；保留原作者历史信息差异，无法控制则不单归因“独立性”。共同生成前缀的成本在每臂整链成本中一致归属，实际现金账只付一次，不隐去它；这类复用局部实验不得冒充全新完整链路重复。

〔补〕8run是共享24内申请，不是独占批准。统一登记 task、trial、条件与实现hash、环境、初态、干预和证据；同一冻结运行多模块复用只计一次，日志重分析不算新run，新尝试／复验计新run。共用前缀复用与完整新运行分别标记，保留原失败分母。隐藏题见后只解释失败，需新确认题支持修订结论。余额不足优先关键控制复验，否则报告未排除竞争解释。

〔冷〕控制适用项先判，确认失败不能用均分抵消；质量以正确、完整、可用、返工的任务特定0—3锚点分别报告，开发校准后冻结，不加权总分。盲评先产物与终态，再轨迹，交换顺序并做独立人工校准。运行成本含父子、通信、等待、合并、失败、重试、验证、恢复；评分研究、准备建设、迁移分别列，NA不填0，不把token当钱。

〔补〕因实际遥测／方差未知，本计划不把144run说成费用上限。每层token／墙钟上限、超时终止与不能硬限的替代测量，在获批开发校准方案中先给临时上限，开发后冻结隐藏批次参数；不得先无界开发再补预算。模型或权限无法固定则限定环境内解释。数据缺口不强迫增加平台分支或全端重复。
