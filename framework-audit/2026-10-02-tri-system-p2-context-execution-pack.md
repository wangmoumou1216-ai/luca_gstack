## 零、所有后续 Session 必须继承的背景

**luca_gstack 是在 Codex 桌面、Codex CLI、Claude Code CLI 中通用使用的一个框架。评估按三体系及其协同作用组织，最终产出一份统一的评估执行计划。** 本文将用户口述的“Cloud Code”按 Claude Code 理解；该名称不改变通用框架这一评估对象。

用户本次明确要求：“按照它们的通用价值，然后去考虑我的框架上面的这几大模块的问题以及计划的输出。”据此，以下约束适用于目的整理、研究、独立规划、设计、审计、比较、裁决和迁移：

- **以共同用途定义价值。** 从理解任务、组织执行、保持信息连续性和必要的人类控制出发，研究框架在当前模型与实际运行环境能力之上增加了什么价值；这些价值是否值得其规则、协调和维护成本。
- **保持一个框架的规划对象。** 不按三个使用端拆成三套方案、三组模块或平台专项 Session，不预设需要新增适配层、平台分支或配置体系。若证据表明统一目标存在无法消除的能力冲突，记录影响并回到共同用途裁决，不由执行者自行扩大架构。
- **区分能力事实与架构选择。** 模型本身的能力、环境实际提供的执行能力、框架增加的机制，分别作为归因依据。环境名称不充当方案分组依据；必要的能力核实服务于同一方案的可行性判断。
- **通用性不等于采用最弱能力。** 不要求实现方式完全相同，也不凭空假设各处都有同一能力。无法取得必要能力时，先检验现有能力能否以更简单方式达到同一结果；仍不能满足必要控制或用途时明确限制，不静默削弱目标。特有增强的收益不能冒充通用收益。
- **以证据控制复杂度。** 每个保留或新增机制都要说明服务的共同用途、必要能力前提、最小替代及净价值。确需核实环境差异时，只检查可能改变结论的行为与控制点，复用同一任务和判据；不得以此自动扩成全端、全组合的独立评估工程。
- **按模块职责限定范围。** 三体系评估负责通用的任务分流、Agent 协作、Context 提供及其交接；技能内部领域方法、动效或其他具体交付流程仍由技能 owner 负责。技能作为真实任务的消费方或案例时，只检查与三体系有关的输入、输出和控制衔接。发现技能内部问题，记录具体责任边界，不自动扩大为技能重构或新增评估模块。
- **允许高价值交集优先进入。** 主协调者可将直接改善共同用途或评估可信度、且能保留最新提交有效行为的交集列为优先项。先复用现有 owner；确有额外收益才设计最小增补实验，并记录收益依据、责任边界和回归要求。优先项使用既有任务卡，不新增阶段或审批体系，也不扩大实施授权。

## 2. 必要步骤、顺序与判法

路径为CX-00准备中性输入与事件需求 → K冻结开发例 → CX-01独立设计与CX-02静态审计隔离并行 → 双方冻结后首次解盲 → CX-03薄试件/driver与运行可比性 → CX-04开发校准及后续隐藏观察 → 有决定价值才CX-05诊断/反证/终版复验 → CX-06建议与迁移交接。角色是职责，不等于每一格开新Agent；当前不启动这些执行者。

角色定义：K为案例/答案保管者，不参与候选设计修复；D为目标导向独立设计者；A为现状审计者；E为试件实现/运行者，不能唯一验收自己；J为非作者评分/方法复核者；R为未参与被挑战条件设计或运行的独立挑战者。主协调负责分配、解盲、预算和统一集成；Context持续负责人负责模块合同、证据回收、接口与建议，不兼任D。相容职责可合并，独立边界不能靠角色改名消除。

静态审计必做但只回答结构、声明与用途，不能证明消费或恢复。局部实验仅用来回答会改变决定的能力缺口/竞争解释，不以检索命中代任务质量。完整可运行比较才支持改造推荐；不可测时可以交静态或有限可行性结论。先整链后局部，禁止为了证明Context有用而无限加例。

同题固定模型可核查配置、工具、权限、任务验收、原始事实和总资源上限；信息选择、提供时机与压缩是变量，不强迫最后prompt相同。B为现状、T为原生最薄、S为针对性精简、I为独立候选，最多4个；T仍有必要目标/授权/约束/原始资料入口，不能故意缺信息。排除或合并须有证据，只有一个可运行条件时不作相对收益结论。

先核授权、人工决定、更正、失败传播、完成真实、消费和恢复控制；确认失败不被高均分或节省token抵消。再以任务锚点分别评正确性、完整性、可用性、返工各0—3，开发后冻结可接受差异；不加权总分、不以“不显著”证明等价。J先看匿名产物及终态再看过程；专业质量沿原技能owner判据，不扩成技能重构。作者自评不能唯一验收，模型辅助交换答案次序并复核分歧/控制失败；无人类校准则披露限制。无法比较的质量成本取舍留给用户，先提交可审阅证据。

- **Owner/输入/禁区**：Context负责人写`u004c-context-diagnostic-request.md`；R/J独立反证/验收。输入为冻后差异、原分母、匿名证据、版本/预算及未见集可用性，不是隐藏答案；禁事后改标准。
- **动作**：最多两类诊断：一次只改位置或干扰；或者连续/恢复。写竞争解释、哪种结果改变决定、完整矩阵、复用记录精确ID、共享余额与停止点。完整链无决定相关差异则不跑；R挑战额外真相、更多计算、评分和多因素混淆。
- **依赖/验收/预算**：U-008差异与诊断必要性成立，协调分配余额后E执行；两条件×两分支×两重复=8run，只有4次精确匹配基线才新增4，开发每题仅一次不能自动满足2重复。全部追加共24、优先留8终版复验，Context没有独享8次。R/J调用扣32池，默认反证/定向修订合计最多2轮。
- **出口/续点/删除损失**：输出支持/反驳/不确定；修复后用未见材料核终版，耗尽则不推荐未验变更。修复者只接缺陷与必要脱敏资料，不泄漏确认答案。恢复被冻结争议、版本、余额及下一最小动作，不重开研究。删除则把相关性当因果。

### CX-06｜U-011—012：形成建议、迁移及三Agent实施交付

- **Owner/输入/禁区**：Context负责人唯一写`u004c-context-implementation-handoff.md`，主协调整合总体建议/迁移。输入为终版裁决、用途账、真实成本/限制和推荐范围；不执行生产切换，不把未测兼容当已测。
- **动作/产物**：每项机制列共同用途、能力前提、最薄替代、质量/成本差异、残余风险；有效用途必须落到已验证新路径、暂留旧路径或待用户接受退出。标信息含义/允许变化、在途状态解释、恢复与回退证据、接口及维护/迁移成本。改变不值得可推荐现状。
- **依赖/验收/预算**：依赖U-010终版结论；J核无静默用途丢失，领域owner核消费接口。0默认新run；写包/复核扣32池，必要恢复可行性试验先申请24剩余额度，缺证据就标限制。
- **出口/续点/删除损失**：必要用途无去向保留旧路径，不推荐切换；恢复读终版证据与处置表。删除会留下不能实施的成绩比较。

## 5. 信息事件、恢复和条件性分支的具体合同

K在每条适用事件冻结：event/task/资料版本、来源及权限依据、主体/对象/范围、生效点、替代或撤销关系、可见对象、触发条件、可接受与禁止的下一动作、终态/过程观测位置。时间更晚不等于有权更正；冲突未决时事前明确需要澄清还是停止依赖动作。答案只进K/J专用视图，不给候选作者；所有条件获得同一原始事实和用户回答事件流。

六桶交叉安排四种Context观察：信息充分无需交接；关键事实夹在干扰中；冲突/有效更正/过期决定；固定节点中断后继续。隐藏至少2题恢复，其中1含更正或授权变化，并覆盖假完成、应停和应继续。标签可重叠，叠加因素的失败只作问题发现，不强归单因素。K制作具体题并校验预期，无须先知道候选架构。

**开发到隐藏的固定顺序**：先用6开发例校准；冻结条件实现、提示/资料、driver、控制清单、0—3锚点、容差和试次顺序；K再单独封存12隐藏例、答案和事件脚本。隐藏开始后每题每条件两次、预登记交错顺序，新执行上下文之间不共享输出/分数；模型seed不可控则明记。根据已见隐藏题修复的版本须用未见确认材料，旧成绩不能继承到终版。J输出每题/每次原值、分层配对差及波动；样本不足的区间/效应不确定就直接说明，不强报显著性。开发评分通用语义起点：0=错误或不可用，1=重大缺漏/需大幅返工，2=可用但有局部缺漏/轻量返工，3=该维度达到任务要求；具体维度锚点由K及领域owner在开发例校准，控制失败另判，不能用等级替代必要控制。

**计划中断**：预登记语义事件点暂停某一run，留当时产物、成本、允许持久化材料和真实内部状态；不同条件的内部组织可不同，不能统一快照而抹掉被测变量。恢复者只取其条件合法可得资料，从检查点续做同run；新Session不自动等于新trial。连续分支获得相同更正/授权事实。各完整分支独立计1run，前后阶段成本都计入。

**故障后继续/重跑**：事前脚本规定是否允许续段以及失败是否终止试次；续段仍保留原失败事件/分母/全成本，不事后喂额外真相。如果从原始初态完整重做，分配关联新run扣追加，原结果保留。实际中断点或状态不同则记协议偏差，不按匹配对照推因果。可恢复声明只有实际后续动作和终态证据支持才成立。

**有限分支**：输入污染→封存并重做受影响部分；运行污染→阻断相应因果比较；原生T已满足用途且无增益→停止加复杂度；质量提高但成本也升→交并列证据给用户；波动/基线不足→优先缩小问题或只报未归因；确认集耗尽→停止可靠性扩展；技能内部失败→原owner处理、不扩三体系改造。任何出口都保留版本与分母。

## 6. 资源池、扣池和停止

采纳统一稿的公共技术预算，替代session-plan旧的30/90分钟、20k输入、人工工时配额和Context预留8次建议：简单run20分钟/40k可观测总token/30工具动作，重run60分钟/120k/90动作，父子合计、最多3条整链并发。可控项设硬限；token只能结束后取得则为事后观测，靠可执行时间/动作停止并披露非严格等token。缺基本取消能力不启动对应运行。

开发6×最多4×1≤24，隐藏12×最多4×2≤96，共≤120；追加24含能力/driver、故障新尝试、诊断和终版复验，总≤144。追加先留8复验，探针至多6，余下最多10按决定影响分配；不用的额度不自动花完。Context最多两类申请而非两类必跑。少条件就减少分母；追加分配由主协调单一ledger扣减。

准备/设计/审计/试件共20工作调用；评分/复核/建议共32。每个实际派发/子派发/修复重派均计数，限45分钟/90动作，120k token按可测性披露；多个卡合并同一次派发只扣1。CX建议不是额外池，是否复用D/A/J/E已有派发写入登记。运行角色的完整试次列run池，独立准备/评分列工作池；若探针发生在准备派发内，run和派发两种数量都登记，但同一模型/工具usage仅在费用账记一次，不能重复相加。内部父子重试计原run资源，不隐藏成本。

输入目标16k token、审阅检查点24k；无精确计数记录字符数，不造百分比。完整零节、授权/更正/责任/失败分母不截断，日志按获准索引定向读；必要超限明确原因后分证据批次。摘要≤2,000中文字符，本模块通常≤500。准备、评分、运行、人工等待与一次性建设迁移分账，缺遥测记NA、无价格不换金额。

任何池到限停止依赖增量的工作，报告余额、未回答的决定和缺证代价；不能改名字续费、事后抬赢家上限或降低控制。开发后可在现有天花板内统一减少限额；增加限额在隐藏开放前据实测提交总体裁决。当前P2文档工作不冒充已经消耗未来评估run。
