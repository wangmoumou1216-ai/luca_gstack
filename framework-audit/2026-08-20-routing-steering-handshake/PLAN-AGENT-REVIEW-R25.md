### Repair 1 — §4.2 `NEG` "complete inventory" claim (lines ~510–522)

The plan now defines `NEG = 不|不是|不要|别|不用|无需|不必|没|没有|甭|勿|未`, groups it as 不-family / colloquial imperatives (别, 甭) / literary imperative (勿) / perfective-existential (没, 没有) / aspectual (未) / formal (无需), and explicitly excludes `非` with a stated rationale ("negates a nominal predicate … never yields `非进入`"), inviting future additions only when a corpus case demonstrates a directive-scoping negator is missing.

Adversarial check — is any predicate-scoping Chinese negator still missing:

- **`莫` (mò) is missing and is a real gap.** `莫` is a standard literary/classical negative-imperative marker that directly negates a directive verb in modern usage, most visibly in fixed prohibitive signage and formal register (`闲人莫入`, `生人莫近`, and directly analogous to the enumerated set: `莫进入 luca app 项目` is grammatical and unambiguously means "do not enter"). It sits in exactly the same register as the already-included `勿` (both are literary imperative negators) but was not enumerated and was not given an exclusion rationale the way `非` was. This means the enumeration is not actually complete as claimed, and the specific input `莫进入 luca app 项目` (or `莫切到 luca app 项目`, etc.) would resolve as an **affirmative switch** under the current grammar instead of being cancelled — a real behavior change (false-positive project switch), not merely a documentation gap.
- `毋` (wú, classical equivalent of `勿`, still seen in formal writing) is a secondary, weaker candidate for the same reason; less central than `莫` but same category of omission.
- Checked whether other candidates are actually already covered or are false leads: `不曾`/`未曾` (aspectual "never") are compounds around `不`/`未` already in the set and are marginal/unnatural in directive-cancelling position (`不曾进入 luca app 项目` reads as "have never entered", not an imperative cancellation) — I do not count these as gaps. `休`/`休要` (archaic "don't") is arguably a fourth candidate but is rarer than `莫` in contemporary text; I flag `莫` as the primary, clearly-demonstrable miss and `毋`/`休` as secondary evidence that the "complete inventory" framing itself (rather than one more patched word) is the recurring root cause across R18/R21/R24/R25.
- `非` rationale check: sound on its own terms — `非` is a contrastive/classifying nominal negator (`非项目`, `非请勿入`'s `非` sets up the exception clause, it does not itself negate `入`) and I could not construct a natural `非<directive-verb>` reading. The exclusion of `非` specifically is not the problem; the problem is that `莫`/`毋` were not even considered under the same rationale test the plan applied to `非`.

### Repair 2 — §4.2 quoting-suppression rule (lines ~499–508)

Rule as written: a quoted/backticked span is ignored (suppressed) **iff it contains the directive verb**; a quoted span that **contains only the target** is unwrapped and selection proceeds on the unwrapped clause. Unbalanced delimiters are explicitly not a quotation and suppress nothing.

Adversarial inputs tried:

1. **Unbalanced delimiters** — explicitly handled by the text itself ("An unbalanced delimiter is not a quotation and does not suppress anything."). No gap found.
2. **Nested/mixed-type quotes**, e.g. a `『「luca app」』`-style nesting around only the target — the outer span still "contains only the target" once nested delimiter characters are treated as part of the quoted content rather than as independent quotation boundaries; behavior is inferable but the plan does not state how nested delimiters of different families are collapsed before the "contains only `<target>`" test is applied. Minor ambiguity, not scored as a separate finding (folds into finding 2 below, since it is the same underspecified third case).
3. **A quote spanning the verb but not the target**, e.g. `「进入」luca app 项目` — the quoted span contains the directive verb, so the whole span is suppressed/ignored; what remains outside the quote (`luca app 项目`) then has no directive verb at all, so nothing authorizes. This resolves correctly and consistently under the stated rule; not a defect.
4. **A quote containing a negator**, e.g. `「不进入」luca app 项目` — the quoted span contains the verb (alongside the negator), so it is suppressed under the verb-containing rule regardless of the negator; consistent, not a defect.
5. **A quote containing the target plus a non-verb, non-negator token — the actual gap.** Construct `进入「luca app 的」项目` (quoted span = target + one trailing-content token `的`) or `进入「luca app 项目」` variants with an adjacent particle/report token inside the quote instead of outside it. This span (a) does not contain the directive verb, so the "ignore iff contains verb" clause does not apply, and (b) does not "contain only `<target>`", so the "unwrap when target-only" clause does not apply either. **The rule as written has no third disjunct and therefore does not define an outcome for this input class.** This is exactly the interaction the round brief asked to attack ("a quote containing a negator", generalized to any quote containing the target plus one extra non-verb token — a negator, a trailing-content token from the closed set, or a report/example token) and it is a genuine gap: an implementer cannot mechanically decide suppress-vs-unwrap-vs-something-else from the current text.

**Verdict on repair 2: the intended asymmetric-quoting fix (citation-of-target-alone unwraps; quoting-the-directive suppresses) is sound and correctly resolves the two paired examples the plan gives, but the grammar is not closed** — a quoted span containing the target plus any other single non-verb token (negator, particle, trailing-content token, report token) falls through both disjuncts with no defined behavior. Severity: MAJOR (a real class of currently-unresolvable inputs for the alias grammar, which §14/§4.2 claim to fully enumerate).

**Minimum repair for both:** (1) add `莫` to `NEG` (and evaluate `毋`/`休` under the same rationale test §4.2 already applies to `非`, either including or excluding each with a stated reason, the same way `非` was handled) with one positive fixture per new member; (2) add an explicit third disjunct to the quoting rule, e.g. "a quoted span containing the target plus any other token, none of which is the directive verb, is treated the same as an unquoted occurrence of that content" (or the opposite — treat it as suppressed like the verb-containing case) — either choice closes the grammar, but the plan must pick one and add the matching fixture(s), rather than leaving the case undefined.

## Findings

1. **[MAJOR] §4.2 `NEG` alternation is still incomplete — `莫` (and secondarily `毋`) missing.** `莫进入 luca app 项目` (and analogous `莫切到`/`莫回到` forms) would resolve as an affirmative switch instead of being cancelled, under the grammar as currently enumerated, despite the section's explicit "this is the complete inventory" claim and its `非`-exclusion rationale not being applied to `莫`/`毋`. Location: `FINAL-EXECUTION-PLAN.md:510-522` (definition), `561-571` (§5.1 shared use), `4830-4839` (§14 fixture requirement).
2. **[MAJOR] §4.2 quoting-suppression rule has an undefined third case.** A quoted span containing the target plus exactly one other non-verb token (a negator, a trailing-content token, a report/example token, or a nested-quote artifact) matches neither the "contains the verb → suppress" disjunct nor the "contains only the target → unwrap" disjunct, so the grammar does not mechanically specify an outcome for e.g. `进入「luca app 的」项目`. Minimum repair: add one explicit third disjunct stating the outcome for "quoted span contains the target plus other non-verb content" (either treat identically to plain suppression, or to plain unwrapping, with a fixture for the chosen behavior). Location: `FINAL-EXECUTION-PLAN.md:499-508`.
3. **[MINOR] Five envelope-tracked check/verify scripts are not explicitly named in §16's minimum command union.** `scripts/verify-codex-wiring.mjs`, `scripts/check-project-routing.mjs`, `scripts/check-registration-sync.mjs`, `scripts/check-capability-parity.mjs`, `scripts/check-agents-parity.mjs` are §12.2 tracked paths but do not appear individually in the `L0`–`L3` minimum command union (`FINAL-EXECUTION-PLAN.md:5591-5629`); only `bash scripts/verify.sh` might subsume them, and the plan does not state this the way it explicitly caveats `npm run verify`'s aggregation. Minimum repair: either name these five scripts explicitly in the minimum command union, or add one sentence stating that `scripts/verify.sh`'s wiring to these five pre-existing scripts has been separately reviewed (mirroring the existing `npm run verify` caveat).
