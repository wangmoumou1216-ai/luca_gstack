### MAJOR-1 — `NEG` negator inventory is incomplete for the third consecutive time, causing provable false positives in both consumers

**Contract conflict.** §4.2 defines the canonical alternation once: `NEG = 不|不是|不要|别|不用|无需|不必` (`FINAL-EXECUTION-PLAN.md:493-494`), and §5.1 explicitly reuses it verbatim for the structural-negation generated sets (`:527-528`, `:5001` R-SIGNAL confirms the "full seven-member" set). §5.1 additionally asserts "no generic negation heuristic and no other negator/verb pair is admitted, and the two negation grammars in this document share one negator alternation with no unexplained asymmetry" (`:538-540`) — i.e., the plan claims completeness for the negation surface it defines, not merely internal consistency between its two consumers.

This is the **third** time this exact class of gap has been found and patched piecemeal: Round 18 added `别`; Round 21 added bare `不` (closing an omission that had let `不进入 luca app 项目` wrongly authorize a switch). The seven-member set that resulted is still missing ordinary, common Mandarin negators: **`没`/`没有`** (aspectual negation — "hasn't/didn't"), **`甭`** (colloquial contraction of `不用`, i.e. `不用`'s own informal register), **`勿`** (formal/written imperative negation, e.g. `请勿…`), **`未`** (formal "not yet"), and **`非`** used outside the single whitelisted idiom `而非结构` (e.g. a bare `非结构问题` rather than `不是结构问题`). A full-document grep confirms zero occurrences of `没`, `甭`, `勿`, `未` anywhere in the plan, and `非` occurs only inside the one fixed phrase `而非结构`.

**Mechanical counterexamples against current bytes** (both consumers are hit):

1. *§5.1 structural-signal false positive*: `我们优化了设置页面的颜色，结构没变。` ("we optimized the settings page's colors; the structure hasn't changed"). Evidence spans: change = `优化` ✓, interface = `设置|页面` ✓, structure = `结构` (embedded in `结构没变`) ✓ — three distinct legs present. The generated negation set only recognizes `NEG × (改|动|调整|变) × 结构` / `结构 × NEG × (改|动|调整|变)` / the two fixed idioms; `没变` matches none of them (`没` ∉ NEG). ### MAJOR-2 — Substring-quoted alias target inside an unquoted directive: resolution is genuinely undetermined by the current bytes

**Contract conflict.** §4.2 states the authorization precondition at the *clause* level: "Only an affirmative project-selection clause outside quotes/backticks/report/example spans authorizes aliases" (`:474`). Separately, in the clause-segmentation rule: "Clause boundaries are start/end and ，,。；;！!？?\n. Ignore quoted/backticked spans." (`:494`). These two sentences license two materially different, non-overlapping implementations for the same input class, and the document does not disambiguate which is required:

- **Reading A (boundary-detection scope):** "ignore quoted spans" governs only how the algorithm locates clause boundaries — i.e., don't let a comma or period *inside* a quoted span fragment the clause. Under this reading, a quoted product name that contains no internal boundary punctuation (e.g. `"luca app"`) doesn't change clause segmentation at all, and the surrounding directive `进入 "luca app" 项目` is scanned and matched normally — it resolves.
- **Reading B (authorization-suppression scope):** "ignore quoted spans" extends the same treatment used for reported-speech exclusion (`他说"进入luca app项目"`, a frozen negative example at `:517`) down to the sub-clause level — i.e., *any* text inside quote marks, even a bare product-name citation, is excised from the scan before matching. Under this reading, `进入 "luca app" 项目` has its `<target>` position emptied by the strip, the verb+marker pattern no longer has a target to bind, and the clause **fails to resolve** — reproducing E1 (the exact class of bug this plan exists to fix) under an entirely ordinary, non-adversarial Chinese stylistic convention: quoting a proper noun for emphasis or citation.

I searched the full document for a worked example that would settle this — the only quote-related examples given are `他说"进入luca app项目"`-style **whole-clause** reported speech (excluded under both readings, so it cannot disambiguate) and the abstract report/example token list (`比如|例如|示例|测试短语|文档写着|引用|假设`, `:499-500`, which are *lexical* tokens, not quote marks, and don't bear on this either). No fixture in `R-ALIAS` (`:4799-4801`) or anywhere in §15's mutant list exercises a bare substring-quoted alias inside an otherwise plain, unquoted directive. **I therefore report this as genuinely undetermined by current bytes — not as a proven wrong transition in either direction** — which is itself the defect: an "executable grammar, not a model label" (§8.1's own self-description, `:3488`) cannot leave a materially input-changing ambiguity unresolved for a plausible, everyday input and still claim to be mechanically total.
