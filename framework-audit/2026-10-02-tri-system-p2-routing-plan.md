**2．三种评估深度的适用边界**

| 方法 | 可以支持的决定 | 不能支持的决定及升级条件 |
|---|---|---|
| 只做静态审计 | 找出触发含糊、责任冲突、不可达分支、重复要求；重建规则声称保护的用途，形成待测清单。 | 不能证明选择实际改善质量、没有隐藏用途或可以安全删除。涉及实际触发、负担、恢复及下游损失时，需要行为证据。 |
| 直接局部实验 | 在已冻结、可执行的处理路径间，核实某次选择、澄清或升级是否改变后果；适合定位端到端差异。 | 局部选对不能证明整链成功。路径本身能力不同、输入组织改变或协作重做时，须回到完整链路；不把局部实验扩成孤立路由排行榜。 |
| 完整设计与行为比较 | 对当前、精简、独立候选与最薄对照，比较可检查成果、必要控制及整链成本，判断机制净价值。 | 成本最高；仅对可行且非等价条件实施薄原型。不存在公平运行条件时限定结论，不靠设计文档评分替代行为比较。 |

顺序采用上游的“先完整链路、后有条件消融”。静态审计用于建立事实和风险清单，不先用旧标签筛掉独立候选；局部实验用于解释已经观察到的差异，不承担总体优选。

**3．任务卡与 U-005—U-012 映射**

以下各卡共同继承完整第零节。共同生产记录包括输入清单、版本、实际注入、访问记录与恢复点；发现禁区泄漏即停止受影响工作。规划阶段没有发生下列执行动作。

**卡 R1｜U-005：从用途提出路由可检验假设**

- **决策问题与来源：**哪些任务差异确实需要不同处理，哪些显式选择可能只是增加步骤？来源为目的契约、U-003 的 S1/S4/S7 方法结论及开发案例。
- **共同用途与必要能力：**让简单任务及时完成，让重任务获得足够能力与控制。必要前提是可以观察请求、真实授权、可用执行能力和可检查结果；不预设存在特定路由工具。
- **白名单／禁区：**允许中性目的、经过污染审查的能力事实、开发案例、方法合同；禁止旧实现、旧审计、隐藏答案，以及 U-006 未冻结结论。能力事实不能夹带旧规则或其阈值。
- **动作与产物：**由独立设计者在 P3 提出选择责任、最小替代、适用前提和失败预测，形成“用途—待验证选择—预期后果”清单。每项说明为何直接处理可能不足，以及显式选择额外要求了什么。此处只规定交付内容，不给出候选方案。
- **职责与依赖／验收：**U-005 生产；独立方法审查者检查目标忠实性、输入独立性和可证伪性。依赖共同能力事实包与开发案例冻结。验收要求删除旧机制名称后仍可解释成功，且每项机制都有最小替代和反例。
- **预算与停止／恢复：**建议最多 2 人时路由专项工作，计入统一设计预算，整链 run 为 0。假设及反例齐备即停止；能力不明记录条件化预测，必要控制无法判断则暂停相关假设，保留已冻结部分。
- **删除损失：**候选可能复制旧分类，或以更复杂的选择流程冒充目标导向设计。

**卡 R2｜U-006：重建当前选择行为及其有效用途**

- **决策问题与来源：**当前选择保护了哪些结果，实际在哪里增加负担或传递错误？来源为审计侧获准访问的当前版本、历史材料及真实行为证据；历史声明须与当前行为区分。
- **共同用途与必要能力：**保持已有效的用途、授权控制及恢复能力。需要能定位实际入口、触发和后续执行；不能仅凭配置名称推定生效。
- **白名单／禁区：**审计侧允许旧实现、获准历史资料和对应运行记录；冻结前禁止独立候选方案。未经逐案授权不得读取 Muse 或其他下游项目。
- **动作与产物：**逐项覆盖“用途→入口与触发→选择→协作需求→Context 需求→人工控制→故障恢复→证据”，形成用途保护表、选择传播链和缺证清单。保留静态声明与实测行为的差别。
- **职责与依赖／验收：**U-006 生产；非作者审查证据追溯与用途覆盖。行为判断绑定版本、会话、driver 和最终状态；缺行为证据只能标待验证。冻结前不向 U-005 输出机制摘要。
- **预算与停止／恢复：**建议最多 3 人时路由专项审计，复用主实验，不新增独立运行额度。覆盖约定用途和缺口后停止；材料过大则按用途定向补证，不无限追溯历史。恢复须携带已读范围与未覆盖分母。
- **删除损失：**精简可能静默丢掉有效控制，或将历史补偿误判为当前必要机制。

**卡 R3｜U-007、U-008：共享比较矩阵与行为验证**

- **决策问题与来源：**显式选择是否改善最终结果，增益能否排除额外资源、资料差异和下游重做？来源为双方冻结结果、U-003 配对方法和共同预算接口。
- **共同用途与必要能力：**同一任务获得可消费交付，选择过程维持授权与信息连续性。需要能重置任务状态、观察选择及后续动作、核验产物；原生无显式选择记录时，不能凭缺少日志判其失败。
- **白名单／禁区：**第三方集成者可在记录解盲后读取两侧冻结材料；运行者只获得所属条件所需资料；评分者先只看匿名产物和状态。隐藏答案、其他条件产物和评分反馈不得进入执行上下文。
- **动作与产物：**将 B/T/S/I 映射到共同任务和预算，记录合并或排除依据。共享薄原型由实现责任人按冻结方案完成，路由规划者不临场替候选补设计。先运行整链，再按触发条件分配局部实验，产出逐题比较表、错误传播证据和资源账。
- **职责与依赖／验收：**U-007 集成、运行负责人执行 U-008；独立评分者核结果，技能 owner 处理领域验收争议。依赖版本、任务、预算、宿主允许机制和评分规则冻结。候选运行若被旧路由或 hooks 改写，标记污染，不归因给候选。
- **预算与停止／恢复：**复用基础最多 120 run；路由消融申请最多 12 run，占共享 24 run 池，不另加总额。薄原型路由相关实现暂提最多 4 人时，超限先缩减到可回答核心问题的范围，不能偷减必要用途。能力不具备、无法公平比较或预算耗尽时停止相关分支，保留原分母与受限结论。
- **删除损失：**只剩规则解释与主观偏好，无法判断选择是否产生净价值。

**卡 R4｜U-009、U-010：反证、裁决与终版复验**

- **决策问题与来源：**观察到的改进是否来自路径更合适；简单任务是否被多余控制拖累；精简是否遗漏低频高损失场景？来源为冻结比较结果、异常轨迹和 U-003 的竞争解释。
- **共同用途与必要能力：**防止假完成、错误授权及无必要升级。需要可独立检查产物、实际动作、预算和失败分母。
- **白名单／禁区：**挑战者可读冻结方案和结果，不能把新反例透露给候选调优后仍称未见验证；争议复验使用保留案例或重新冻结的确认集。
- **动作与产物：**挑战“更复杂才可靠”和“更薄必然足够”两种假设，检查模型差异、资料泄漏、额外采样、汇总者重做及评分偏差。产出反证清单、裁决依据、未解决冲突和复验记录。
- **职责与依赖／验收：**独立挑战者生产；第三方裁决者验收，领域争议交对应 owner。作者不能唯一验收自身选择。关键缺陷修复后复验终版；证据不足可以裁决为不确定，不要求一致好评。
- **预算与停止／恢复：**建议 2 人时专项审查，默认最多两轮。新增运行仍从共享 24 run 池申请；无足够复验额度则不能将修复后的方案宣布通过。保留版本分叉及未完成复验清单。
- **删除损失：**可能把表面相关当作路由收益，或通过反复调试验证题获得虚假优势。

**卡 R5｜U-011、U-012：路由净价值与用途延续**

- **决策问题与来源：**哪些选择责任值得保留、精简、替换或退出，切换怎样保持用途？来源为最终证据、用途保护表及总计划 P6。
- **共同用途与必要能力：**保持可消费接口、必要人类控制和中断恢复；需要能辨认在途任务的真实状态、授权与已作决定。
- **白名单／禁区：**允许解盲后的冻结证据和获准迁移约束；禁止把未实测设计推断写成已兼容，不开展生产切换。
- **动作与产物：**每项有效用途标注新路径已验证、旧路径暂留或待用户接受退出；列明允许变化、旁路对比、回退触发、在途状态恢复及旧路径退出证据。形成统一建议中的路由部分，不另建平台路线图。
- **职责与依赖／验收：**集成负责人生产，独立验收者与相关 owner 核用途衔接。依赖终版复验和未决冲突清单；不可比较的质量／成本取舍及降低必要底线交用户。
- **预算与停止／恢复：**建议 1 人时专项整理，整链新增 run 为 0。迁移可行性缺证时明确待验证，不以文字推演冒充验证；恢复包保留未处置用途。
- **删除损失：**评估结论难以转为平滑迁移，可能留下无人负责的旧用途和在途任务。

**4．与协作、Context 的责任边界**

路由负责表达选择意图及依据：当前目标、已知约束、授权范围、需要补充的信息、期望交付及改变选择的触发事实。这是评估观察责任，不要求候选新增固定消息协议。

协作模块负责判定分工、执行、合并是否兑现选择需要，并返回能力不足、依赖冲突和责任缺口。路由不替其规定角色数量或拓扑。Context 模块负责信息可达、最新更正、决定来源及恢复材料的正确提供，并返回遗漏、过期和冲突证据；路由不替其规定记忆层级或压缩结构。

端到端失败至少覆盖：

- 选择了不具备必要能力的处理方式，且未纠正，导致错误或不可消费结果。
- 必须澄清的授权或关键条件未解决便行动，或将推测当作用户决定。
- 简单任务被无必要的升级、澄清或交接打断，增加等待、人工负担或返工。
- 选择改变后，旧责任、资料或决定仍驱动下游动作。
- 协作或 Context 已返回不足，路由仍宣称完成或继续错误路径。
- 恢复后沿用过期选择，丢失目标、授权或最新更正。

归因采用“首个可观察偏差—下游响应—最终后果”链。资料未提供可能是 Context 原因，资料已提供但选择忽略可能是路由原因；须凭事件证据判断。允许共同原因和未归因，不强迫每个失败唯一归属。发现技能内部专业问题，转交技能 owner，只保留三体系接口影响。

**5．最小样本、消融与判法**

采用共同接口的六个覆盖桶，各 1 开发例、2 隐藏例，共 18 个任务。开发阶段每条件 1 次；隐藏阶段每条件 2 次。最多四条件对应 24＋96＝120 个整链 run。开发结果只用于校准；12 个隐藏任务、每题两次是探索性比较起点，不足以证明极低失败率。

在这些任务中交叉安排：明确简单任务、信息充分但看似复杂任务、歧义会改变处理方式的任务、缺少执行能力任务、需要人工决定任务，以及中途更正或恢复任务。覆盖授权越界、过期决定、假完成三类高损失事件，不新增全组合矩阵。每题预先写出可接受行为范围；多个路径都可成功时不强造唯一正确路由。

仅提出两种条件式消融：

1. **选择反事实。**当条件间存在实质选择分歧及结果差异、且下游路径都能执行时，固定下游实现、原始资料与总预算，比较实际选择和独立专家事先给定的可接受选择。最多 4 个配对、8 run。专家不得见结果后选择获胜路径；专家路线不是绝对真值。
2. **澄清必要性。**当多问或少问被怀疑造成差异时，在可重置的合成任务中比较澄清与不澄清处理，预先冻结用户回答脚本和隐藏事实。最多 2 个配对、4 run。不向任何条件额外泄露真相，不在真实不可逆任务上取消授权控制。

两种消融均观察最终结果。选择不同但结果等价时只报告尚无增量证据；路径切换、资料组织或执行方式无法分离时，保留交互解释，不声称纯路由因果效果。

判分先核必要控制和可消费结果，再分别评价正确性、完整性、可用性、返工及额外用户负担。建议各质量维度采用带任务锚点的 0—3 级描述，开发阶段校准，隐藏运行前冻结；不加权合成总分。评分先看匿名产物与最终状态，再查轨迹；模型辅助评分须交换顺序并由人工样本校准。

必要控制失败单列，不能用其他维度高分抵消。报告逐层配对差、每题两次结果、失败类型与成本范围，不按未知频率计算总体收益。质量更好但更贵、不同质量维度互有得失且无已批准规则时，交用户裁决；统计不明确则保留不确定。没有可信最终结果核验，不作质量优选。

**6．预算、去重与恢复合同**

路由不另建主实验：共享最多 120 个基础 run，最多申请 12 个条件式消融 run；能力核实和争议复验继续共用总池，统一总上限仍为 144。上述路由专项人工工作合计暂提最多 12 人时，属于总计划内部份额，不应与同一工作重复计费；领域评分与共同准备由主协调统一计账。

技术上限建议按任务复杂度暂设两档：简单任务整链 60,000、重任务 180,000 个可观测输入／输出 token；机器执行墙钟分别 20、60 分钟。包含所有父子执行者、重试和自身验证；缓存分类、人工等待及实际金额另外记录。这些仅是待审阅的探索上限，不代表用户成本偏好，也不保证适配现有能力。开发阶段若发现上限系统性截断任务，应在隐藏阶段前统一修订并重新确认预算；没有 token 遥测时不能宣称实现了严格 token 等预算。

超时、超额、运行失败及非零退出码保留在原分母，说明其阻断或警告影响。重跑使用关联的新 trial ID，不能覆盖首次失败。遥测缺失记 NA；费用未知不得用 token 换算出虚构金额。
