# 改造后的使用方式

> 来源：Codex 快照提交 `b72f753`（`refs/codex/snapshots/` 下）中的 usage-guide-r4.1，2026-10-19 Claude 评估时导入；已对照 `5d95451` 的 `.claude/agents/references/plan-design-guidance.md` 核对仍一致；相对 r4.1 仅补齐场景 C/D 条件措辞。

以下是用法说明，不是“已证明交互更好”的结论（效果评估见 `framework-audit/2026-10-19-frontlight-plan-to-delivery-review.md`）。默认深度未调整：research_depth 默认 deep，discovery_mode 默认 full，focused 需每次显式选择。

## 从当前缺口开始

| 当前情况 | 合适入口 | 下一步 |
|---|---|---|
| 目标、范围、核心机制已清楚 | design-brief | 已选择的生成工具 → 实际验收 |
| 缺关键外部事实或可行性依据 | 对应研究能力 | 回到受影响的产品或交互决定 |
| 不确定做什么、范围怎么取舍 | brainstorm | 根据剩余缺口继续；已定方向不重新发散 |
| 想比较同任务的竞品设计 | ux-research | 可独立结束；需要设计时再继续 |
| 有研究，核心交互已选定 | design-brief | 将已采用条件写入设计规格 |
| 有两个真正不同的交互机制待选 | ux-brainstorm | 解决取舍，再进入 design-brief |
| 现有界面的问题还没定位 | ux-audit | 基于实际问题局部研究或设计 |

A/B/C/D 描述任务背景，不是必跑清单。真实线上改版仍保留审计基线、同范围复验、P0 与评分要求，不能改标为 B 来规避；Agent 化任务的角色、权限、确认/接管和恢复未定时，不能当成熟输入直接跳过。

## 可以直接这样提出请求

**只做轻量竞品分析：**
“用 ux-research，显式 focused。围绕【用户任务】比较【材料或对象】，重点回答【1–3 个会影响设计的问题】。只交付研究，不继续设计。”

可只给设计问题，再决定比较范围；不必先写 PRD。已有链接、截图、录屏也可以作为材料。focused 使用一名研究者，检索/材料/状态/截图读取共享 8 项初始预算，保留原独立审查；不是每个竞品各有 8 项预算。缺材料就限制相应结论。

**已有明确交互，直接产设计规格：**
“用 design-brief。原始需求是【需求】，已确定的交互是【机制】，附上【可选研究材料】。保留已有决定，补全状态、反馈、恢复和验收条件。”

**需要选交互机制：**
“用 ux-brainstorm，显式 discovery_mode=focused。目标已经明确，未决的是【具体交互取舍】，请比较机制和代价，给出主任务与关键异常的走读。”

普通原始问题也能独立调用 brainstorm、ux-brainstorm；缺研究报告不等于必须补跑整链。复杂且新颖的问题仍遵守既有研究确认门。

## 研究怎样进入设计

研究记录观察、证据类型、可比条件和未知。接收设计的 skill 说明采用、调整、放弃或暂缓的理由。真正采用的条件进入 Brief 的决定、状态、页面语义位置与验收，再进入唯一 Generation Packet。最终检查实际界面有没有实现、实现后是否改善任务。

例如，研究发现了一个适用的恢复机制：必须先确认它补上了当前缺口，再写成可操作的失败/重试验收。若原始需求或直接 Brief 本来已有这个机制，不能把它记为新增研究收益。证据支持保留原方案或排除具体风险可以有价值，但与交互改善分开报告。

## 出问题时只回到对应位置

- 事实不足：补对应问题的证据。
- 产品或交互取舍有冲突：交回该决定及真正需要作选择的人。
- 已定机制漏了状态或验收：补 Brief。
- Packet 正确，HTML 没实现：修生成产物并复验受影响部分。

保留其他已确认决定与稳定编号。局部返工减少重复工作，但不省略受影响的检查。
