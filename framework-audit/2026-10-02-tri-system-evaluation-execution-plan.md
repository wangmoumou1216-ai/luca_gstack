# 三体系统一评估执行计划 v2 — 三模块完整子计划统合

日期：2026-10-02。当前状态：待独立方法审查。

## 零、所有后续 Session 必须继承的背景

**luca_gstack 是在 Codex 桌面、Codex CLI、Claude Code CLI 中通用使用的一个框架。评估按三体系及其协同作用组织，最终产出一份统一的评估执行计划。** 本文将用户口述的“Cloud Code”按 Claude Code 理解；该名称不改变通用框架这一评估对象。

用户本次明确要求：“按照它们的通用价值，然后去考虑我的框架上面的这几大模块的问题以及计划的输出。”据此，以下约束适用于目的整理、研究、独立规划、设计、审计、比较、裁决和迁移：

- **以共同用途定义价值。** 从理解任务、组织执行、保持信息连续性和必要的人类控制出发，研究框架在当前模型与实际运行环境能力之上增加了什么价值；这些价值是否值得其规则、协调和维护成本。
- **保持一个框架的规划对象。** 不按三个使用端拆成三套方案、三组模块或平台专项 Session，不预设需要新增适配层、平台分支或配置体系。若证据表明统一目标存在无法消除的能力冲突，记录影响并回到共同用途裁决，不由执行者自行扩大架构。
- **区分能力事实与架构选择。** 模型本身的能力、环境实际提供的执行能力、框架增加的机制，分别作为归因依据。环境名称不充当方案分组依据；必要的能力核实服务于同一方案的可行性判断。
- **通用性不等于采用最弱能力。** 不要求实现方式完全相同，也不凭空假设各处都有同一能力。无法取得必要能力时，先检验现有能力能否以更简单方式达到同一结果；仍不能满足必要控制或用途时明确限制，不静默削弱目标。特有增强的收益不能冒充通用收益。
- **以证据控制复杂度。** 每个保留或新增机制都要说明服务的共同用途、必要能力前提、最小替代及净价值。确需核实环境差异时，只检查可能改变结论的行为与控制点，复用同一任务和判据；不得以此自动扩成全端、全组合的独立评估工程。
- **按模块职责限定范围。** 三体系评估负责通用的任务分流、Agent 协作、Context 提供及其交接；技能内部领域方法、动效或其他具体交付流程仍由技能 owner 负责。技能作为真实任务的消费方或案例时，只检查与三体系有关的输入、输出和控制衔接。发现技能内部问题，记录具体责任边界，不自动扩大为技能重构或新增评估模块。
- **允许高价值交集优先进入。** 主协调者可将直接改善共同用途或评估可信度、且能保留最新提交有效行为的交集列为优先项。先复用现有 owner；确有额外收益才设计最小增补实验，并记录收益依据、责任边界和回归要求。优先项使用既有任务卡，不新增阶段或审批体系，也不扩大实施授权。

本节是共同输入合同，必须随最小任务包和跨 Session 交接传递。执行者不能只读某一阶段而丢失本节约束。

## 2. 方法依据与必要步骤

目的和必要边界以用户及总计划为准；公开研究只帮助选择取证方法，不证明本框架有收益。冻结研究《2026-10-02-tri-system-p1-research.md》含 8 个一手来源、8 次网页调用，已到规划所需深度。AI Agents That Matter 的网页版本日期有疑点，不能用该页作为精确时间证据；旧模型长上下文研究不能套作当前模型效应量。没有复现论文或新建 benchmark。

| 深度 | 能回答的问题 | 本次采用方式与删除损失 |
|---|---|---|
| 静态审计 | 规则意图、用途、矛盾、入口与责任、明显不可行条件 | U-006 必做；去掉会漏有效用途。不能单靠条文数量认定冗余或收益。 |
| 局部实验 | 一个具体能力或竞争解释是否成立 | 仅有证据缺口可能改变决定时做；默认不跑。去掉会限制归因，不必然阻断描述整链差异。 |
| 独立方案与完整链路比较 | 现状、精简、独立候选与原生最薄对照能否交付同样结果 | U-005/007/008 用于支持改造建议；去掉只能给审计意见，不能证明净价值或安全替换。 |
| 独立反证与迁移检查 | 结论能否抵抗偏差、有效用途如何延续 | U-009—012；去掉容易把偶然成功、隐藏回归带入切换。 |

采用先端到端、后条件消融。每个机制均回答共同用途、必要能力、最小替代、预期收益、成本和失败预测。现状不必被淘汰；证据不足时保留现状是合格结果。框架差异、模型差异与宿主能力分别列账，不按平台分成三套架构。

## 3. 责任、输入隔离与冻结顺序

角色表示责任，不要求每个角色常驻一个会话。同一人/Agent 可以先后兼任不冲突角色；下面的独立性边界不能合并。

| 责任 | 生产/管理范围 | 不可兼任或读取的范围 |
|---|---|---|
| 主协调（本会话） | 目的、进度、资源池、依赖、解盲记录、集成与最终交付 | 已读现状，不担任 U-005 独立设计者；不作唯一验收者 |
| 独立设计者 D | 从中性目的和开发案例推导一份三模块协同候选 | 禁旧实现/审计/主检查点/未解盲现状结论；不得接触隐藏答案 |
| 现状审计者 A | 固定版本的用途与行为声明账、证据缺口 | 冻结前禁 D 的方案；不向 D 夹带现有架构要求 |
| 案例保管者 K | 脱敏开发/隐藏案例、任务级答案、事件脚本和盲评密钥 | 不设计/修复候选，不向作者泄露隐藏案例和答案 |
| E-build 与 E-run | 前者按冻结条件做薄原型；后者逐试次重置执行和留证 | E-run 每次新上下文，不继承 E-build/其他 run 历史；只得本条件本任务材料，不见答案/他条件输出/反馈 |
| 独立评分/方法复核者 J | 先匿名产物和终态，后过程控制；解释争议 | 不参与被评方案制作；不能按已见胜负改权重 |
| 独立挑战者 R | U-009 反证，核查竞争解释、分母和归因 | 不兼任被挑战条件的作者或运行者 |
| 三个模块规划/执行 owner | 规划 owner 交完整子计划；主协调确认后由三个执行 owner 负责模块审计/观察/建议/交接，复用唯一主实验 | 不各自复制主实验；有现状上下文的会话不得冒充干净设计者 |

**冻结顺序解决循环依赖：**主协调确认执行范围 → K 与 F 的中性前置工作 → K 在 D/A 启动前制作并冻结 6 开发与 12 隐藏例，F 只核会影响可行性的能力 → D 与 A 隔离并行、各自冻结 → 不同 J 上下文分别复核 → 主协调记录首次解盲 → U-007 比较矩阵/薄试件 → U-008 开发与成本校准 → 条件/评分/driver 最终冻结，核对原封存隐藏集 → 批次 B 按统一门释放。能力事实确需改题时保留新旧版本，由未见候选胜负者复核理由及覆盖，不能见开发输赢再选择有利隐藏题。A 先冻结静态声明和未知，U-008 后追加行为证据，禁止回写初版掩盖预测。

J 是职责统称，禁止复用不兼容历史：J-K/F 可核含隐藏答案的案例，J-D 只看 D 的白名单及方案，J-A 只看 A 的材料。知隐藏答案的上下文不得给 D/E-build 调优反馈；双侧冻结前审查意见不得泄漏另一侧。主协调不需读取隐藏内容，由获准确定性流程按 K 预制映射提供单题输入/匿名评分包，逐次调用及实际成本留证。

D 每次必须先披露自动注入；输入独立性和运行独立性分开验证。P2 已采用仓库外只读 CLI、定向 stdin、无工具事件；这支持限定输入规划，不证明 P3 设计或 P4 运行已隔离。P3 必须使用新上下文并逐次检查。不能将已经看过框架规则的三个可见会话直接作为独立设计者。

运行隔离在 U-007 单独验证：每个条件使用可重置副本/临时目录，显式列出允许的提示、规则、技能和 hooks。B 保留当前机制；T/S/I 不得被旧机制暗中改写。不得在全局配置中关闭控制或越过平台安全要求；只在获准的隔离试验范围配置。若必要运行边界无法成立，记不可测/受污染，保留记录并缩小结论，不靠新聊天声称解决。

每次派发复制完整第零节，再加入适用于该角色的任务卡、白名单/禁区、版本 hash、读写范围、依赖、验收与余额。D 仅收经非作者核查的中性投影：完整零节、目的、研究/能力事实、开发题与必要方法；不传本稿、三份 execution-pack 或 session-plan 全文。§4.3 现有取证 owner 仅约束 A/E 评估侧，不作为 D 的架构输入。索引不授读权。恢复包保留实际输入/已读范围、已完成与失败、最新决定/授权、责任、剩余预算及下一动作。

## 4. 统一比较、案例和测量

### 4.1 条件及共同事实

- B：固定基线版本的当前三体系。
- T：原生能力加完成任务所需的最薄提示与资料；仍有相同工具权限、必要事实和控制底线。
- S：根据现状证据做针对性精简；候选制作在 A 冻结后进行，清楚列删去什么及其用途去向。
- I：D 从目的独立推导的三模块协同方案，单独冻结后解盲。

最多四条件。U-007 若证明 S/T/I 机制和可观察行为等价可以合并；不可行可以排除但要记录具体缺失能力和同用途最小替代检查，不能因预计表现差而排除。B 缺失时不得输出“优于现状”。至少保留可运行 B 与一个有区别的对照才能做相对比较。若只剩一个条件，输出可行性/静态结论。

同题固定原始材料、可用工具、权限、初始状态、任务验收、可核查模型配置和总资源上限。信息选择、组织、提供时机是待测变量，不强制各条件最终 prompt 完全相同。跨模型/跨宿主绝对分数不混作框架增益。按实际必要能力风险补查其他宿主的同任务控制点，使用共享额度，不做三端全组合。

### 4.2 案例矩阵与隐藏保护

以下只给覆盖目的，不是隐藏题目或答案。K 在 D/A 启动前从脱敏合成材料构造并冻结开发与隐藏内容；读取 Muse 等真实项目需逐案明确授权范围，当前没有该读取授权。

| 层 | 开发/隐藏数 | 主要观察 |
|---|---:|---|
| 简单有界任务 | 1 / 2 | 完整交付、不必要澄清/升级/分工负担 |
| 框架维护 | 1 / 2 | 变更边界、有效行为保护、失败传播 |
| App 功能 | 1 / 2 | 真实需求与可消费交付、能力不匹配的修正 |
| 设计工作流 | 1 / 2 | 已定设计决策、领域 owner 与通用控制衔接 |
| 工程工作流 | 1 / 2 | 依赖、验证、合并和实际终态 |
| 需求到设计落地 | 1 / 2 | 长链、更正、授权和中断恢复 |

共 6 开发＋12 隐藏。覆盖层不是使用频率和互斥任务总体，不计算频率加权总收益。复杂度与层交叉：开发 2 简单/4 重、隐藏 4 简单/8 重；由 K 按工作量预先划档，不按结果重新贴标签。隐藏内至少 2 可独立分解、2 强依赖、2 不值得分工、2 固定节点中断；其中至少 1 恢复含最新更正或授权变化，另覆盖过期决定、假完成、失败子任务。标签可重叠，不扩成笛卡尔积。

K 写每题可接受行为范围而非唯一正确路由，附相同用户回答脚本、中断点、结果检查与适用控制。事件包含来源与权限依据、主体/对象/范围、生效点、替代/撤销关系、可见对象、触发点、允许/禁止的下一动作；文本更新不自动授予权限。所有条件同一原始事实和事件流，专业技能故障正确暴露/停止/恢复可判控制通过，不能把故障注入本身直接判失败。D 和实现者可见开发题及评分方法；隐藏具体题目/答案在专用保管范围，执行者每次只见当前请求与应得资料。受控访问信任边界、实际访问记录与哈希必须披露，不冒充 OS 隔离。

开发允许修订，记录所有初次结果。隐藏开始前冻结候选、提示/配置、原始数据、driver、评分锚点与顺序。候选执行运行使用新上下文，跨条件和跨试次不传结果。每题每条件两次，使用预登记交错顺序；明确 API seed 是否可控，不能虚称确定性。隐藏已见后调优形成新版本，旧成绩不得算到终版；复验用未见确认材料，额外次数从共用池扣除。材料用尽即停止扩展可靠性主张。

### 4.3 同一证据供三个模块使用

run = 一个任务版本 × 一个条件版本 × 一次从指定初态到最终检查的完整尝试；连续/恢复或其他干预分支各算一次。其内部所有父子执行、重试、自检、合并均计入该 run 的资源。基础批次首次尝试失败仍在原分母；重新从初态启动的试次是关联新 run，扣扩展池，不能覆盖失败。计划中断从该 run 预登记检查点继续，保持同一 ID、失败事件及全部前后成本，新会话不自动变新 trial；连续/恢复两完整分支各 1 run。故障续段按事先脚本处理，不能重做冒充恢复。各条件只恢复本来合法可得的状态，不用统一快照抹掉 Context 变量。独立评估者的评分/研究不算被测系统运行成本，另行计账。

唯一登记字段：task/condition/trial/perturbation ID；模型配置/可证实程度；宿主与允许机制；源/提示/实现/driver/数据 hash；初态与终态 identity；原始 stdout/stderr/exit；工具与模型事件；结果路径；失败/污染类别；评分；输入输出 token（缓存单列）、调用、工具动作、父子合计、墙钟、等待、人工介入和重试。缺遥测记 NA，不记零，不凭 token 换虚构金额。传输层不可见重试另列不可观测成本限制。

对同一 run 三模块分别标事件：路由意图与改选；协作职责/依赖/回收/合并；Context 提供/访问/消费/更正/恢复。首个可观察偏差→后续响应→最终后果，允许共同原因或未归因。信息没提供、提供没消费、消费后选择错、正确结果合并丢失要区分。共享事件只算一次失败；不得三模块重复扩大样本数。

沿用现有 evidence-receipts、project-verification、verification-exit 方法：先冻结 required 分母与源版本，再保留实际操作与终态证据，cleanup 后仍可读；非零退出、超时、错实例、缺片按真实结果传递，不以 doctor/静态 hash 代行为通过。不新建通用调度器或平行证据协议。U-006 先映射现有 suite，U-007 只补无法覆盖的行为入口。

### 4.4 评分及优选

每题先核适用必要控制：授权不扩大、人工决定不伪造、最新更正生效、失败不掩盖、完成状态真实、交付可消费、恢复连续。任务含应停与应继续的对照，不能以一律停止冒充授权安全。确认失败不能被高均分或省 token 抵消；标明故障适用范围，修复终版复验前不推荐该范围切换。

再按任务锚点评正确性、完整性、可用性、返工/用户负担，各 0—3 级，开发校准后冻结。领域标准由原技能 owner，三体系不另造专业审美/工程标准。J 先盲看产物和终态，后查过程；模型辅助盲评交换展示顺序，至少复核所有控制失败、分歧和各层一个样本。人工校准若无法取得，披露仅模型/可执行检查的评分限制，不声称已人工验收。

不加权成单个总分。先排控制失败；按层展示每题两次质量和成本向量。质量相当须在开发时写明可接受差异与锚点，不用“不显著”冒充等价。12 隐藏题×2 是探索性证据，不证明极低失败率或总体统计显著。质量提升但成本也升、不同行为互有得失且无既定规则时，列出实际增量交用户裁决，不能把“适度”自行解释为任意倍数。

## 5. U-005—U-012 可派发任务卡

所有卡共同继承第零节、§3 输入隔离、§4 中与角色相容的测量条款和 §6 预算；D 必须使用上文中性投影，不能因此收到集成稿全文。下列产物名是未来文件的建议名，当前不存在，不作为已完成证据。每卡独立包必须带这些共同条款全文/所需内容，不能只有摘要链接。

### U-005｜目的导向独立设计

- 决策/来源：目的契约、P1、三模块独立底稿；哪些机制为共同用途必需，原生最小替代在哪里不足。
- 用途/能力：正确分流、足够组织与信息连续性；委派、访问和恢复等前提须列已证/待证。
- 白名单/禁区：中性目的、审过的能力事实、开发集、方法合同；禁旧机制、A 未解盲材料、父检查点、隐藏题与答案。
- 动作/产物：D 形成一个整体候选，不是三套局部架构；逐项列用途→能力→最小替代→失败预测→接口→成本；输出 `u005-independent-design.md` 与输入清单、冻结 hash。
- 生产/验收：D 生产，J 独立检查目标忠实、污染记录、可证伪性和用途覆盖；不提前评优于现状。
- 依赖/门：开发集和中性事实先冻结；完整产物与输入检查通过才解盲。默认一次初稿、一次针对性修订，计准备调用池，0 行为 run。
- 停止/恢复：禁区注入则封存受影响产物，换合格输入上下文重做受影响范围并扣成本；必要能力不明用条件假设，不能伪造可行性。
- 删除损失：只能在旧机制中修补，失去独立替代和自证复杂度的对照。

### U-006｜当前体系用途与行为审计

- 决策/来源：固定当前版本、授权范围内历史与轨迹；哪些有效用途必须延续，哪些控制是声明/观察/推断。
- 用途/能力：有效控制、输入输出、交付及恢复；需要版本化读取和真实终态取证能力。
- 白名单/禁区：本框架固定副本、既有相关 suite/合同和开发例；禁 D 未冻结方案、隐藏答案、未授权下游项目。
- 动作/产物：A 沿用途→入口→分流→协作→Context→人工控制→恢复→结果建账，区分未验证与已有效；输出 `u006-current-use-evidence.md`，含已查/未查分母和 U-008 待验证项。
- 生产/验收：A 生产，非作者复核关键主张与源；技能 owner 核领域交付边界。每个保留/删除建议必须有用途或证据依据，不能仅以现行条文为真值。
- 依赖/门/预算：与 U-005 并行，互不看结论；独立冻结静态账后可解盲，待验证不虚判失败/通过。最多一次初稿一次补缺，计准备池；正式行为只复用共用运行。
- 停止/恢复：材料缺失则缺口明确，按用途定向补查，禁止无限翻历史；版本漂移复核受影响范围。删除损失：可能把有效控制当冗余，或把历史补偿永久化。

### U-007｜集成比较与最薄可测实现

- 决策/来源：已分别冻结 D/A、P1 和模块建议；哪些不同条件值得测，如何公平运行。
- 用途/能力：同样成果与必要控制，能重置、终止、取证；使用实际能力，不能从 CLI 版本推定。
- 白名单/禁区：解盲后的 D/A、开发集、获准隔离实现范围；作者禁隐藏资料。主协调记录解盲后才给 E。
- 动作/产物：主协调固定 B/T/S/I、合并排除理由、用途保护矩阵、共同接口、driver 和角色；E 按冻结方案建薄原型，J 查输入及运行污染、重置/终止/留证；输出 `u007-comparison-manifest.json`、可执行入口与缺口。不制作四套生产框架。
- 生产/验收：主协调＋E 生产，J 检查同题事实、权限、模型证据与资源可比，owner 检查可消费接口。薄原型作者不自行宣布公平。
- 依赖/门/预算：D/A 已冻、开发例已就绪；缺重置、关键污染或终态核验则阻断对应行为比较。实现与方法工作共用准备池；D 之前 F 的中性能力探针与 U-007 候选 driver 探针共同占最多 6 次/扩展 24 池。每探针先冻结最小输入、观察、终止和留证，不依赖尚不存在的完整 driver；只读既有可信回执不扣行为 run，人员成本照记。成功后不例行重复。
- 停止/恢复：超建设预算先削到能回答决定的范围；仍不足报不可测，不偷偷减必要用途。删除损失：设计停在纸面，比较条件或宿主污染可左右胜负。

### U-008｜开发校准与隐藏验证

- 决策/来源：冻结矩阵、用途/任务级验收、§4；哪种条件能以值得的成本交付。
- 用途/能力：覆盖简单与重任务、必要控制和恢复；重置、取消、真实资料/结果检查及成本记录就绪。
- 白名单/禁区：E 只读本次条件及任务材料；J 先匿名产物，后过程；隐藏答案仅 K/验收者可读。禁止将评分反馈喂回未结束的确认运行。
- 动作/产物：先开发最多 24 run，校准后提交 A 回顾；B 获准再隐藏最多 96 run，保留首次结果、逐层配对与整链资源，输出 `u008-runs/`、`u008-results.md` 和原分母/observed。
- 生产/验收：E 生产，J 独立查所有适用控制与产物；争议用同一 owner 判据。模型或权限漂移、driver failure、污染、遥测缺失分别列项。
- 依赖/门/预算：§3 全冻结、批次授权、预算可执行；失败不改分母，额外试次扣扩展池。完整链无差异则不强开消融。
- 停止/恢复：关键安全/隔离故障立停受影响范围并保留原始记录；到限停止，不以重命名续费；计划中断按 §4.3 从检查点续同 run；从任务初态重做才关联新 run 并扣池，比较受限照实写。删除损失：无法判断实际净价值。

### U-009｜独立反证

- 决策/来源：冻结结果、原始证据、预注册判据；最可能推翻推荐的漏洞是什么。
- 用途/能力：防额外计算、资料、评分偏差、偶然成功、合并重做冒充机制收益；需要独立查证。
- 白名单/禁区：R 可读完整冻结证据和异常；禁未授权项目/见结果后改底线，反例不得作为调优资料又称未见题。
- 动作/产物：提出竞争解释、反例、决定影响及最小复验；输出 `u009-refutation.md`，同时挑战过度复杂和过度精简。
- 生产/验收：R 独立生产，主协调核可检验性，J 复核争议；不要求所有人同意。
- 依赖/门/预算：U-008 证据完整；默认最多两轮，属于审查池。新增实验只用 §6 扩展池。
- 停止/恢复：没有改变决定的争议即止；有关键缺口就交 U-010，不无限增加题。删除损失：发现阶段的解释未经挑战就变成推荐。

### U-010｜裁决与终版复验

- 决策/来源：反证、分歧、原判据；能否解决到足以推荐。
- 用途/能力：避免假完成、漏控制和修复未验证；实际重放、未见确认材料、版本绑定。
- 白名单/禁区：冻结争议及定向证据；修复者只拿缺陷，确认答案保管；不能追认修复前成绩为终版。
- 动作/产物：J/非作者裁决者给支持/反驳/不确定，登记受影响范围；关键缺陷修复后执行实际终版复验，输出 `u010-adjudication.md`、终版 hash 及残余限制。
- 生产/验收：主协调组织，J 独立验收；不可比质量成本或降低底线由用户决定。
- 依赖/门/预算：默认与 U-009 合计最多两轮；必要复验优先用共享保留额度。预算/未见题耗尽则不推荐未验版本。
- 停止/恢复：标准不因预算降低，遗留冲突保留。删除损失：没有终版证据、争议悬置或用讨论取代执行核验。

### U-011｜净价值建议

- 决策/来源：终版证据、用途矩阵、完整成本、争议；保留/精简/替换/退出哪些机制。
- 用途/能力：改善共同结果且保全必要控制；真实任务占比仍未知，不作总体年化收益。
- 白名单/禁区：全冻结证据；禁将设计推断写实测、以文件变少/旧测试通过代收益。
- 动作/产物：主协调合并三模块为 `u011-recommendation.md`，每项列用途、前提、最小替代、质量/成本增量、不确定性、交互及决定；分别列一次性建设/维护/运行成本。
- 生产/验收：模块 owner 供证据，主协调生产，J 非作者核结论追溯；用户裁决不可比权衡。
- 依赖/门/预算：U-010 通过或清楚限制；0 新 run，计审查/建议池。缺证则保留现状或条件建议。删除损失：实验分数不能变成可行动决定。

### U-012｜用途延续、迁移方案与三 Agent 实施包

- 决策/来源：U-011、有效用途/控制/恢复账及用户并行执行要求；如何切换而不静默丢失价值。
- 用途/能力：每个有效用途有已验证新路径、旧路径暂留或待用户接受退出；在途状态可识别、回退可执行。
- 白名单/禁区：解盲后的证据和具体获准迁移范围；禁止在本卡执行生产切换，禁止未实测兼容性写已兼容。
- 动作/产物：主协调输出 `u012-migration-and-three-agent-workpacks.md`；按 §9 冻结接口、独占文件、共享 owner、验收和回退。每个保留用途写允许变化、旁路比较、分批切换、回退触发、状态恢复和旧路径退出证据。三包是未来实现输入，不用模板替代未知具体设计。
- 生产/验收：三模块会话供内容，主协调统一，J 查每项用途去向与包间依赖，领域 owner 核接口。
- 依赖/门/预算：U-011 已定；0 新 run，必要恢复/迁移可行性验证须从剩余池申请并标试验，不能冒充生产迁移。建议/任务包具体可审阅后再按确认范围实施。
- 停止/恢复：任一必要用途无去向就停止推荐切换并保留旧路径。删除损失：三个局部改动可能破坏共同接口或在途任务。

## 6. 统一预算、容量与停止规则（提议，待用户审阅）

### 6.1 数量与阶段

| 池 | 上限 | 释放条件 |
|---|---:|---|
| A 开发整链 | 6 题×最多 4 条件×1＝24 run | 批次 A 批准、U-007 可执行性通过 |
| B 隐藏整链 | 12 题×最多 4 条件×2＝96 run | A 回顾通过，规则冻结、原隐藏集未污染；主协调在获准范围/上限内释放 B，超出则提交实际增量给用户 |
| 全部追加 | 共用 24 run | 每次写未回答的决定、固定因素、成本、优先级；非模块独享 |
| 全计划 | 最多 144 run | 所有新试次、能力检查、故障重跑、消融、争议和终版复验都在内 |

追加池先保留 8 run 给关键控制/终版复验，能力与 driver 探针至多 6，余下最多 10 按影响分配。探针未用可转诊断，保留的 8 只有确认不需复验才释放。不接受三模块各加额度：路由建议 12、编排 8、Context 8 合计 28，不能并行全部兑现。每模块最多提 2 类消融，是否执行由共享证据缺口决定。

恢复实验必须数清分支：2 条件×连续/恢复×2 次＝8 run；仅存在 4 个同版本/事件流/预算的匹配基线时新增 4，否则申请 8 或缩小问题。不把“一组配对”计一个 run。位置/干扰同理，先写完整矩阵再扣已存在的精确匹配记录。

诊断存在复用公共生成前缀时：每臂的整链比较成本一致计入该前缀，实际支付账只记一次；标为复用前缀的局部诊断，不能充当全新端到端重复。两种编排消融优先排额外计算解释：并行分工 vs 同总预算单执行者顺序尝试，比较到完成合并的最终交付，顺序尝试的选优也计成本；独立审查 vs 自检固定待检产物及目标，修复和终态核验计整链。自检臂保留冻结原作者续接状态或可核等价重建，独立臂用预登记可见包；记录历史可见性和恢复成本。做不到则只称不同输入包的诊断，不能单归因独立性。路由反事实的可接受选择须由未见结果者对新配对实例事先给定，不能让已见胜负的专家指定获胜路径；澄清消融用合成回答脚本，不在真实任务撤销授权控制。Context 每次只改位置、干扰或中断之一，不能多因素同时变而声称纯因果。位置/干扰亦需未扰动与扰动两分支：1 题×2 条件×2 分支×2 次为 8 run，只有 4 次精确匹配基线才新增 4。

### 6.2 资源上限及校准

为使批次 A 有可审阅边界，提议简单 run 墙钟 20 分钟/可观测总 token 40,000/工具动作 30，重 run 60 分钟/120,000/工具动作 90，父子合计；最多 3 条完整链同时运行。工具动作按实际操作计，不通过打包多命令绕上限；父子等待时间同时记录实际墙钟和汇总资源。每 run 只能用其获准资料与权限，底线不能为了“等预算”删除。

这些是探索技术上限，不是预估耗时、用户价格偏好或模型容量。U-007 先验证监测与取消：可测且可控项目使用硬限；token 只能结束后返回时标为事后观测上限，使用墙钟/动作作为可执行限并披露无法严格等 token。若连整链取消或最基本计数均无法实现，停止对应运行，不能用数字承诺硬限。

A 的 8 简单＋16 重基础 run 对应最高可观测 224 万 token、累计链墙钟 18 小时 40 分钟；全基础 40 简单＋80 重对应 1120 万 token、93 小时 20 分钟，追加全按重任务再最多 288 万 token/24 小时。是极端上限，非预估价格或用户等待时长，且不含另列的准备/评分；这正是先做 A 再决定 B 的原因。实际开发完成后，按逐层实际中位数/范围给出 B 预测，不盲目用尽上限。

准备/设计/审计/薄原型共用最多 20 次顶层 Agent 工作调用；评分/复核/建议共用最多 32 次。每次最多 45 分钟、90 工具动作，可观测 token 提议上限 120,000（可控性按上一段披露）；初稿、定向修复、重派都扣池，不能靠开新会话归零。20/32 次只统计实验工作人员派发及其工作子 Agent/重派；被测条件在已登记 run 内的父子 Agent 全计该 run 的资源，不重复扣工作人员池。外层运行管理/分析若另派人则扣工作池，直接机械启动/采集记录实际工具成本。两本数量账可关联，实际 usage 费用只计一次。手工阅读/审阅时间记录但不编“Agent 人日”；三个模块原始的工时提案被此统一池替代。任何需要超池的工作先报告具体余额、收益与缺证代价，停止依赖该增量的工作。

不要求花满。少条件节省的次数默认不再花；资源足够也不自动扩大问题。开发校准可在现有天花板内减少/统一限额，增加限额须在隐藏开始前用实测依据提出并确认，不看隐藏结果后调高获胜条件。

## 8. 模块接口裁决与共享改动

路由负责“当前理解/已确认约束/授权/缺口/预期交付/改变选择的事实”；编排负责“职责/依赖/执行可行性/合并/失败反馈”；Context 负责“信息可达/有效性/来源/更正/授权与恢复材料”。这些是评估责任，不强迫候选增加协议。

端到端失败包括错误选择后未纠正、子任务失败被遗漏、过期决定驱动动作、正确结果在合并中丢失、授权推测变成权限、恢复后漏做/重做、不可消费产物被声明完成。专业技能错误交原 owner，不扩大三体系重构。

预算由主会话一处扣减；数据由 K 保管；driver、比较矩阵和公共接口由 U-007 单一 owner；三个模块只提交需求/证据，不同时改共享文件。无法独立完成的接口变更先串行冻结，再并行模块内部工作，不能为了速度制造三份不兼容合同。

## 9. 最终方案形成后的三 Agent 并行实施与统一提交

1. U-012 将已定推荐转换为三个精确包：路由、编排、Context。每包列目标与不变行为、基线 SHA、独占文件/允许新增文件、公共输入输出与错误语义、依赖版本、验收命令/真实行为、回退与交付证据。文件清单在方案形成后由主协调从真实影响分析填入，不以模块名代写范围。

3. 能解耦的模块内部改动并行；真实依赖采用完成通知/固定版本解除。接口要变更由主协调裁决并通知受影响者，禁止各自临时兼容、偷偷扩范围或复刻一套公共层。
