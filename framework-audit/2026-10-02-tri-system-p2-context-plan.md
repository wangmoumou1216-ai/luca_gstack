**4. 与另两模块的输入、输出及失败责任**

以下是交由主协调对齐的接口提议，不假定另两模块已有同样方案：

| 交接方向 | 责任与交付 |
|---|---|
| 分流→Context | 分流模块负责表达当前任务理解、已选处理方式、尚待澄清事项及选择证据；Context 检查依据是否可追溯、过期信息是否影响选择，不决定分流架构。 |
| Context→分流 | 提供信息可用性、冲突及有效性观察，指出哪些缺口可能改变选择；不凭信息不足自动要求升级。 |
| 协作→Context | 协作模块负责责任分配和交接事件；Context 检查证据、决定、更正与权限是否在必要时点到达责任承担者。 |
| Context→协作及下游 | 输出交接缺失、来源冲突、恢复后责任不明等证据；协作 owner 判断分工及合并是否适当，技能 owner 判断专业结果。 |

端到端失败按实际后果记录：遗漏导致误行动；旧决定压过有效更正；未经授权的推断成为行动权限；恢复后重复、遗漏或错误延续工作；交付虽声明完成却不可消费。信息已正确提供但被忽略，不能直接归因于 Context；须区分提供失败、消费失败、选择错误和合并错误。

每个失败使用一个共享事件 ID，可有多个解释标签，但不重复计算失败次数。争议由整链证据解决，不能让模块分别修复自己的局部指标后宣称整链通过。

**5. 样本、条件式实验与判法**

采用共同接口的六个覆盖桶：每桶一开发例、两隐藏例。开发共六题，每条件一次；隐藏共十二题，每条件两次。覆盖桶不代表真实频率，也不作为独立总体。由主协调在十八题中交叉安排简单／重任务、连续／恢复、明确／歧义、独立／强依赖，不做笛卡尔积。

Context 建议至少覆盖四组观察：信息充分且无需额外交接；必要事实夹在干扰中；有来源冲突、最新更正或过期决定；固定中断后继续任务。隐藏集至少两题包含中断恢复，其中一题含授权或有效决定变化；另保留可核验的假完成陷阱。关键控制不只依赖单个案例，可嵌入不同用途，但不能将叠加因素的失败强行归因于其中一个因素。

最多两类条件式实验：

1. **位置或干扰扰动。**仅当遗漏与信息组织有关且可能改变决定时启动。固定原始事实及答案，每次只改变关键事实位置或无关信息量之一。选择一题、两个冻结条件、各两次，最多新增四 run。观察最终行动和信息消费，命中率只作辅助。
2. **中断恢复对照。**仅当恢复差异或能力未知影响推荐时启动。在相同任务事件点中断，使连续与恢复分支获得相同的更正、冲突和授权事实，检查恢复后的行为。选择一题、两个冻结条件、各两次，最多新增四 run。

两类实验都优先复用具备同任务、版本、事件流和资源条件的主实验记录；没有匹配记录时不能冒称配对证据，须由主协调重新分配共享池。若一次同时改变多项因素，只能归因于该组合。八个新增 run 是诊断预算，不保证定位所有失败。

评分先核必要控制及可消费结果，再分别报告正确性、完整性、可用性、返工与重复波动。已知关键控制失败不能被均分或节省 token 抵消；是否影响整个条件或特定适用范围，依据故障边界及复验证据决定。未观察到失败不等于证明不存在失败。

质量相当须有预先定义的实际容差，不能以“不显著”代替等价。容差由开发案例和 owner 判据校准，在隐藏运行前冻结。逐层质量改善伴随更多成本时并列展示；没有用户确认的价格权重或“适度”倍数，不代替用户完成不可比取舍。

**6. 总预算、去重与 Session 容量**

基础预算维持最多 120 整链 run；所有消融、能力核实和争议复验共用最多 24，统一上限 144。Context 建议在共享池内预留至多八次，实际执行前仍按决定价值排序；它不是模块独享额度。少于四个条件时照实减少，不把余额自动用完。

作为可审阅的技术起点，建议简单任务每 run 上限 30 分钟、可观测整链 token 40,000；重任务 90 分钟、120,000 token，任一可可靠计量的上限先到即停止。它们是探索上限，不是用户成本偏好，也不要求花满。六题开发校准若表明任务无法在此完成，须在隐藏集开放前统一调整同题各条件预算。token 无法可靠累计时记录 NA，使用可执行的时间与工具调用计量，明确不能宣称 token 等预算；重任务须支持取消和进度记录。
