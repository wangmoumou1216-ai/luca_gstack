# Design Brief 3.0 — convergence contract and evidence

Framework NO_PIN. Baseline `d6acaf21e89e4c662289c716f7dcd4d3102751e0`. User authorized research, capability/flow implementation, supervision, review, tests, commit and ordinary publication. No product-state write, template source modification, live OD generation, or memory promotion.

## Problem and final architecture

The previous Brief forced PRD for external generation and left template adaptation until after facts were frozen. The corrected stage is: ready design input → inherit/normalize source → choose template and semantically adapt location/actions/states → complete decisions/acceptance → freeze unique Packet → verify final binding/TAC/adoption → OD. A user-selected template is reused; unresolved ambiguity does not silently become reference_only.

Three inputs: selected pipeline artifacts; existing written/spoken requirements; existing prototype + permitted UI change/preserve scope. Six capabilities: source inheritance, spoken intent normalization, semantic template placement, state/action capability conflict resolution, bounded downstream freedom, unified generation and acceptance. Design-source PASS permits generation; only actual PRD end-to-end coverage permits the engineering chain.

## Runtime boundaries

`adaptation_draft` binds the independent current source inventory/revision and actual catalog/source. Each source/state has full source text, purpose, exact position, action, state evidence and uncertainty. Unknown states and alternatives cannot report ready. Original locations are checked through the inert Chromium index including hidden template scopes. ADAPTATION_READY grants neither final binding nor execution; semantic truth remains model/user reviewed.

Prototype evidence is actual bytes + media type + purpose + existing source IDs + hash, within the immutable inventory and full readback. It does not execute HTML or replace Packet facts. No-attachment bundles retain existing wire structure.

UI-only `refine` is separate from structural add/modify/remove. Original refinement checks valid class/style changes; static refinement requires an effective declaration change in a restricted CSS subset and rejects class-only or opaque declarations that may cover it. It changes only exact authorized targets; business DOM/content/behavior attributes, original scripts/global CSS/assets and other regions are preserved. Original profile `original-ui-refinement-v1` uses full target outerHTML; v1 structural innerHTML semantics stay compatible. Refine mixes only with preserve. CSS/class changes can affect behavior or selectors, so byte/DOM checks alone never certify rendered behavior; independent interaction/visual acceptance stays pending.
