**每次证据记录。** task/trial/条件 ID、版本/资料 hash、会话/实例、模型回执可得性、driver、输入/注入、选择/交接、工具输出/退出码、最终状态、独立判分、全成本及异常。非零退出码按阻断/警告传递；环境失败留在原分母，另分能力/执行故障。无可信结果核验则不作质量裁决。

# 总计划 P3—P6 与验收（完整对应章节）

## 三、真正执行计划必须包含的验证链路

### P3：独立设计与现状审计

- **U-005 独立设计者**接收目的、能力证据和开发案例，从目标推导候选方案及其失败预测。
- **U-006 现状审计者**接收旧实现、历史资料和运行证据，重建实际行为及有效用途。
- 双方冻结前不接触彼此结论；冻结后由第三方首次汇合对照。

双方都继承第零节和同一目的契约。设计者从共同用途推导机制，不预设“统一核心＋多个适配层”等架构答案；审计者辨别共同价值、历史补偿和重复控制，环境证据只用于解释实际行为。共享事实包由目的与基线阶段形成并审查，不能由审计侧临时将旧规则包装成能力前提传给设计侧。

现状审计必须覆盖完整用途：

**用途 → 入口与触发 → 行为 → Context 需求 → 人工控制 → 故障恢复 → 证据。**

独立性通过输入清单、工具访问记录、版本和解盲记录验收。`fork_turns=none` 只证明没有继承会话历史，不能冒充物理隔离。若自动注入旧设计约束或访问禁区，重做受污染部分；环境持续无法满足隔离时，应报告限制，不能反复重启后自行宣称合格。

正式评估继续沿用独立上下文：目标导向设计、现状审计、冻结后对照各有自己的 Session。现状审计可按三个体系拆分，但审计材料只在审计侧汇集，冻结前不得通过主 Session 的共享摘要流入独立设计侧。

输入独立与运行独立分别验收。候选运行时若仍被旧 hooks、路由或 Context 注入改写，就不能把结果全部归因于候选；详细计划必须规定测试环境及允许的宿主机制。无法隔离时限制结论，不为取得新方案成绩而修改生产环境。

### P4：公平比较并解释差异

**U-007 建立比较矩阵，U-008 执行行为验证。**

至少考虑三个方向：当前体系、针对性精简、目标导向的独立候选。被硬约束、可行性或等价证据排除的候选，无须继续制作原型。

此外必须考虑“当前宿主原生能力＋完成任务所需的最薄提示与资料”作为对照，以回答自建框架是否仍提供额外价值。它可以与某个候选合并；无法公平纳入时说明排除依据和结论限制，不为凑数量制作第四套系统。

比较的主轴是同一任务上框架机制的增量价值。对照各方在同一实际运行条件内比较；不同模型或环境下的绝对成绩不能直接当成框架优劣的因果证据。环境取样依据共同用途与关键能力风险决定，不按三个端机械复制整套实验。涉及跨环境成立的关键结论时，使用同一行为判据核实其必要前提；证据不足就限定适用范围，不以单处成功宣称全面通用，也不以缺证据自动增加平台架构。

进入实证比较的候选必须能够处理相同任务，产生可检查的结果。详细计划须明确薄原型的实现者、范围和预算；未实现的能力只能作为设计推断。

比较遵守以下条件：

- 主实验固定当前模型、运行参数、可用工具、权限、原始资料与预算条件。
- Context 的检索、筛选、压缩和组织方式是被评变量，不能强行固定最终注入内容。
- 多模型调度若属于待评机制，单独设计实验，避免与架构差异混为一谈。
- 旧模型只有在实际可用、且比较可能改变结论时才纳入；不能用历史成绩冒充同期对照。
- 开发集与隐藏验证集分离，保留验证集首次结果。看过并用于调优的案例不再算未见验证；验证材料用尽也是停止条件。
- 冻结对象包括实际实现、提示词、配置、资料和环境，确保结果对应完整版本。

按完整任务链累计主 Agent、子 Agent、重试和候选自身验证的成本；独立研究与评分开销另列。比较同一总资源上限下的质量，以及达到相近质量所需的资源与用户等待时间；一次性建设／迁移成本与每次运行成本分开。实验批次可使用新 Session，但重置状态和输入条件必须对各候选一致。

先验证完整链路：

**意图 → 路由 → Agent 编排 → Context 交接 → 行动结果。**

再对有争议的机制进行单独或组合消融，解释收益和损失来自哪里；不默认穷举全部组合。

### P5：反证与裁决

**U-009 发起独立挑战，U-010 裁决并复验。**

详细计划必须事先规定方案优选方法：

1. 先通过用户确认的必要控制和关键用途底线。
2. 再依据预先确认的质量、可靠性及效率取舍比较。
3. 将规则与配置数量、用户需要作出的额外选择、协调交接负担、维护与迁移成本、新增失败风险计入净价值；不能仅用 Token 变少或文件变短证明简化成功。
4. 对“更准但更慢”等冲突，预先规定选择规则或需要用户裁决的条件。

不能看到结果后再改变权重，也不能仅凭综合印象打出一个总分。

独立挑战须检查两种相反错误：为追求通用而削弱必要能力，以及为局部能力差异引入不必要分支。若共同用途与实际能力确有冲突，裁决记录缺口、可行的最小替代和影响；涉及降低用户已确认的必要边界时交用户决定，不能自行选择牺牲一端或维护多套体系。

计划方法审查和最终结论反证各有不同对象，均须进行。领域专家只用于重要争议；默认最多两轮，并非必须跑满两轮。修复关键缺陷后复验终版，合理分歧保留。

### P6：价值结论与平滑迁移

**U-011 给出净价值判断，U-012 给出迁移方案。**

每项既有有效用途必须落到以下一种处置：

- 新体系有可验证的新路径。
- 暂时保留旧路径。
- 经用户接受后退出。

不要求每一条旧规则原样存活，但不能静默丢掉用途、控制能力和恢复能力。

兼容以用户结果、必要控制、下游可消费的接口／状态和恢复要求判定，旧步骤只作为证据。每项用途写清允许变化，避免把逐规则继承误认为平滑迁移。

迁移围绕同一套共同用途、规则含义和交接合同组织；必要的入口或执行差异记录在相关用途的验证证据中。最终结论逐项说明保留、精简、替换或退出的机制及其净价值、能力前提和验证范围，形成一份统一建议，不交付三套互相独立的平台路线图。

迁移方案包含旁路对比、按风险分批切换、回退触发条件、状态恢复和旧路径退出标准。评估阶段验证这些安排的可行性；生产切换另行形成实施授权。

## 四、怎样防止遗漏、过度和“审到好评”

以下七项是总计划与下游详细计划的验收标准：

1. **目标忠实：**每个主要目标可追溯到用户的诉求，明确评估一个跨环境通用框架的三体系及其交互；旧做法没有未经论证变成硬要求。
2. **步骤必要：**每一步支持明确决定，并说明删除损失；昂贵步骤有扩展条件，没有按端复制计划、未经证明的适配复杂度或与技能 owner 重复建设的机制。
3. **比较公平：**对象可测，任务与条件可比，优选规则事前确定；模型、环境与框架影响可区分，结论适用范围有证据。
4. **独立有效：**输入、访问、冻结、解盲和污染处置均可核查。
5. **指导可执行：**任务有明确输入、动作、产物、责任、验收及失败出口；各 Session 接到共同输入合同，能力冲突有明确处理方式。
6. **研究有终点：**局部与整体预算、停止条件和证据不足出口明确，不以所有人赞成为结束条件。
7. **结论可落地：**形成统一建议，覆盖三体系交互、有效用途延续和迁移代价，清楚区分实测与推断；通用性没有被偷换为最弱能力交集或无证据的全端可用。

关键缺陷未解决，就修订相关部分；不降低标准换取通过。若充分比较后无法证明改变值得，保留现状就是有效结论。

最终推荐的含义是：**在明确的目标、任务、能力和资源条件下，经过可行替代方案比较与反证，证据最充分的选择。**

Session 拆分另外检查三件事：每个输入包可单独理解自己的任务；交接没有丢掉关键证据或把禁区材料传给隔离角色；统一计划中的跨模块决定已经明确，不留给执行 Session 临场拼接。拆分本身不是收益证明；需要实际记录各 Session 的输入量和交接负担。
