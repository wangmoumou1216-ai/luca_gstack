# Authorized glossary format

The historical filename identifies the upstream reference, not permission to rewrite
root CONTEXT. Use the artifact bound by SKILL.md: an existing authorized owner or the
verified project's `docs/domain/glossary.md`; NO_PIN requires an exact framework artifact.

```md
# {Domain context}

{What this context is and why it exists.}

## Language

**Customer**: The person or organization purchasing the service.
_Avoid_: Account, client

**User**: The person holding a login identity.
_Avoid_: Customer, account

## Relationships and boundaries

{Only accepted ownership/relationship rules relevant to the modeled concepts.}
```

Keep definitions to one or two sentences and include context-specific concepts, not
general programming knowledge or implementation choices. Group natural clusters when
useful. Do not turn a proposal into canonical language without human acceptance.
For multiple authorized contexts, preserve their existing owners and map rather than
creating a root CONTEXT-MAP or inferring the write target. Ask when ownership is ambiguous.
Read existing content before surgical in-place updates; no dated glossary duplicates.
