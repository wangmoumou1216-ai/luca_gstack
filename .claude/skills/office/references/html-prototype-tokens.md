# HTML 原型视觉来源与 AI 状态实现

> 共享 reference，保留文件名与主要节号供现有消费者引用。
> 本文件拥有本地 HTML 的状态呈现和通用可读性；视觉值归当前项目或外部设计系统。
> 不提供旧品牌 token、组件库映射或母版技术要求。AI 状态定义与适用性真值源为 `ai-native-state-coverage.md`。

## 0. 使用方式

生成本地 HTML 前核对已确认的设计来源、目标平台和需求/决策/状态/验收。
下面的 HTML 片段只展示内容和控制位置，未包含事件接线或视觉实现，不是完整可交付原型。
使用者须连接实际状态转换、键盘/焦点、错误恢复，并采用当前项目的视觉规范；验证通过才算实现。
本文件不触发 OD/Figma 写入，不自动选择工具，也不要求复制本地母版。

## 1. 视觉值来源

记录当前项目/设计系统的颜色、文字、间距、圆角、阴影与组件状态来源及版本。
只有已获授权的实际源才可作为实现依据；没有提供规范时可继续一般设计和实现，标明未定项，规范合规写 UNKNOWN。
对比度与操作层级使用 `design-system-contract.md` §六，不从旧品牌表复制默认值。

## 2. 文字层级

区分主要信息、正文/字段值、标签/次要说明、辅助元数据；按实际内容决定需要哪些层级。
同级表现一致，标签和值可辨认，文字保持可读。字号、行高、字重及颜色由当前设计系统决定；
不能用固定四级字号档、某个品牌文字类名或禁用通用字体名单代替验证。

## 3. 间距与密度

组内/组间距离表达相关性；同类元素节奏一致。表格和列表兼顾扫描、内容长度与命中区，
避免文本裁切、拥挤或无理由的空白。间距、行高和断点来自当前项目，不绑定本仓旧数值档。

## 4. AI 专有状态实现

先完整读取 `ai-native-state-coverage.md` 到 FILE_END，为所有非 N/A 状态实现可观察的 UI 和恢复路径。

### 4.1 状态语义与视觉绑定

分别处理思考中、低置信、拒答、部分完成、待 Steer、幻觉兜底、Agent 执行中七态。
颜色、图标和布局可随当前设计系统变化；状态意义、反馈与控制权必须保持。
不能仅用颜色区分状态；用文字或其他可访问线索表达。下列按钮需真正可执行并返回状态反馈。

### 4.2 各状态的内容与控制

#### 思考中态（Thinking / Streaming）

```html
<!-- 骨架占位按当前设计系统实现，保持加载前后的空间上下文。 -->

<!-- 或：流式文字 + stop 按钮 -->
<div>
  <div>
    AI 正在分析...<span>▊</span>
  </div>
  <button>Stop</button>
</div>
```

**禁用：** 普通 loading spinner（无信息量），纯"加载中..."文字（缺少过程感）。

#### 低置信态（Low Confidence）

```html
<!-- 结果以不确定语气和适当视觉权重呈现，文字保持可读。 -->
<div>
  <div>
    <span>AI 建议</span>
    <span>置信度：中</span>
  </div>
  <div>
    {AI 结果内容；注明局限，保留文字可读性}
  </div>
  <div>
    基于有限数据（{具体说明}）。
    <a href="#">提供更多信息提高准确度 →</a>
  </div>
</div>
```

**关键语义：** 结果表达应与依据和置信度一致；视觉降权不降低文字可读性。

#### 拒答态（Decline）

```html
<div>
  <div>
    <!-- 使用当前设计系统的信息提示图标，并核验资产存在。 -->
    <div>
      <div>
        AI 暂时无法给出可靠建议
      </div>
      <div>
        {具体原因：数据不足 / 超出能力 / 需要人工判断}
      </div>
      <div>
        <button>
          {替代操作 A，如"手动查看"}
        </button>
        <button>
          {替代操作 B，如"联系支持"}
        </button>
      </div>
    </div>
  </div>
</div>
```

**禁用：** 冷冰冰的 "Error" / "Cannot process"，空白界面，把能力边界呈现成系统故障（拒答不是错误）。

#### 部分完成态（Partial Completion，agent 场景）

```html
<!-- 步骤清单视图 -->
<div>
  <!-- 成功步骤 -->
  <div>
    <span>✓</span>
    <span>{步骤 1 描述}</span>
  </div>
  <!-- 失败步骤 -->
  <div>
    <span>×</span>
    <span>{步骤 2 描述}</span>
    <div>
      <button>重试</button>
      <button>跳过</button>
      <button>手动完成</button>
    </div>
  </div>
  <!-- 未执行步骤 -->
  <div>
    <span>未执行</span>
    <span>{步骤 3 描述}</span>
  </div>
</div>
```

#### 待 Steer 态（Multiple Candidates）

```html
<!-- 2-3 候选平铺 -->
<div>
  <button>
    <div>候选 A</div>
    <div>{简述特点}</div>
  </button>
  <!-- ... 候选 B、C -->
</div>
<div>
  <button>都不满意，重新生成</button>
  <button>按我的来</button>
</div>
```

#### 幻觉兜底态（Hallucination Recovery）

```html
<!-- 反馈入口（不突兀） -->
<div>
  <span>这个建议有帮助吗？</span>
  <button>👍</button>
  <button>👎</button>
</div>

<!-- 反馈后的确认 -->
<div>
  {反馈实际保存后显示：已记录。未保存时说明失败并提供重试；不承诺未经验证的模型改进。}
</div>
```

#### Agent 执行中态（Running）

```html
<!-- 任务状态入口可持续找到；具体位置由当前设计决定。 -->
<div>
  <div></div>
  <div>
    <div>{Agent 任务名}</div>
    <div>当前步骤：{具体步骤} · 已完成 {N}/{M}</div>
  </div>
  <button>暂停</button>
  <button>查看详情</button>
</div>
```

## 5. 层叠与阴影

浮层、提示、弹窗等应有清晰层级和遮挡关系，阴影/边框服务分组和层叠，避免无目的装饰。
具体阴影和边界处理来自当前规范；不设跨项目的固定数量或强度档。

## 6. 圆角与一致性

同类组件采用一致形态；不同角色的形态差异须有功能或设计依据。
圆角值和头像/状态点等形态由当前规范决定，不使用本仓旧尺寸表作为验收门。

## 7. 动效与无障碍兼容

每个动效记录触发、属性、时长、缓动和序列/延迟，服务状态变化与空间连续性。
时长/缓动按当前项目决定；系统等待反馈时序另见 `interaction-mechanics.md` 主题 4，不能用动画时长代替响应时间。
必须尊重 `prefers-reduced-motion`：在减少动效模式关闭非必要位移、视差、shimmer 和自动播放动画，
保留静态进度、状态文字及停止/暂停入口，不因停动画丢失反馈。避免与任务无关的背景视频或持续运动。

本地 HTML 可按所选状态元素实现下列减少动效分支，并实际验证事件仍可完成：

```css
@media (prefers-reduced-motion: reduce) {
  [data-decorative-motion] {
    animation: none !important;
    transition: none !important;
  }
  html { scroll-behavior: auto; }
}
```

动态演示要分别验证普通/减少动效模式，截图不能证明暂停、键盘或状态转换。

## 8. 消费约定

`html-prototype`、`figma-demo`、`muse-proto-gen` 按需复用本文件的状态和动效语义，保留各自的来源确认、QA 与 AC 门。
`design-brief` 交接状态和必须达成的交互，不把示例 HTML、视觉类名或技术实现写成需求事实。

## 9. 维护约定

新增 AI 状态先更新 `ai-native-state-coverage.md` 的定义/适用性，再同步本文件的实现要求和实际消费者。
项目视觉值留在项目/外部设计系统；引用本地资产时遵守读取权限及 framework/ 只读保护。
维护与交付均核对停止、重试、跳过、手动完成、候选选择、反馈确认、暂停/详情、状态恢复和 reduced-motion。
