# 交互说明写作规范

版本：`1.0.0`。本文件是 prototype-notes 自动生成、人工模板和独立内容审阅的唯一内容权威。
数据记录 `content_guideline_version`；机器结构见 [notes.schema.json](notes.schema.json)，保存与操作见
[contract.md](contract.md)。这是给前端、产品和测试同事的交付说明，不是产品界面微文案或模型提示词。

## 1. 内容边界与依据

说明应让读者知道：何时触发、画面如何变化、哪些操作允许、失败怎么办、怎样返回。
一条说明对应一个模块或动作及其分支；跨模块共同规则放整体规则，不复制到每个标号。
标题使用界面中的具体名称，如“保存修改”“表格筛选”。不为装饰元素或显而易见的点击动作凑条数。

AI 只写本次已冻结生成范围内的全部适用行为，含跨页和隐藏状态；不得为旧模板顺带补规则。
人工可以在整份受支持原型中增加、编辑或删除说明，包括没有元素锚点的整体规则。
来源不足时保留待定项；没有正式 Brief 不等于可以编造业务要求。沿用实际来源 ID，不伪造 D/STATE/AC。
用户已有明确设计确认直接继承；研究建议、模型生成和“采用建议”按钮本身都不构成业务事实确认。

| 说明依据（独立维度） | 正确表达 | 不可推导 |
|---|---|---|
| `confirmed`：实际确认记录或设计规格 | 直接陈述已定规则；折叠“说明依据”给出可查来源 | 已确认不等于已实现 |
| `observed`：当前原型操作观察 | “当前原型：……”并保留实际观察引用 | 不能外推服务端、隐藏角色或未操作分支 |
| `proposed`：建议或待确认 | “待确认：……”点名缺少的决定；建议明确标示 | AI 流畅表述或人工采用不自动提升为 confirmed |

| 原型表现（独立维度） | 给读者的表述 |
|---|---|
| `demonstrated` | 当前原型已演示，依据实际行为记录 |
| `not_demonstrated` | “原型暂未演示：……”；规范可以已经确认 |
| `differs` | “与当前原型不一致：规范要求……，当前表现……” |
| `not_applicable` | 这条没有可演示的原型行为，明确适用理由 |

一条含待确认规则时整体依据保守标为 proposed，细节中仍保留已确认部分的依据。
不把“设计未定”和“规范已定但原型没演示”合写成“低置信度”。原型 bug 不能靠修改说明掩盖。

## 2. 基础写法

采用自然句式：**条件 → 用户操作 → 可观察结果**。条件明显时可以省略；先写主行为，再补例外。
常见长度是一句话或 2–4 条短句，一句表达一项主要行为。字数只是提示，不截断必要规则。
只展开适用细节，不要求每张卡片填满空段落。

| 要求 | 写法 |
|---|---|
| 可实现、可核对 | “输入为空时，点击保存后在该字段下方显示必填提示”，不用“提供完善校验” |
| 具体对象 | 写“更新结果列表”，不用对象不明的“系统完成处理” |
| 条件明确 | 交代禁用条件、恢复条件；禁用和只读分别说明 |
| 失败有下一步 | 交代错误位置、输入保留、修正或重试方式，以及恢复后的去向 |
| UI 写差异 | 写显示/隐藏、布局变化、溢出、滚动、响应式及反馈；不抄完整 CSS 或视觉 token |
| 数值可追溯 | 尺寸、时长、断点、上限及确切提示文字只取确认规范或实际原型；观察值标“当前实现” |
| 缺依据不补造 | 缺数值或设计取舍写“待确认：具体事项”；不填行业常见值，也不借外部设计系统替项目决定 |
| 名称统一 | 同一模块、操作和状态始终用同一个名字；关联其它模块时写实际模块名或稳定标号 |
| 确切文案与解释分开 | 用引号标出需要原样显示的文字；其它句子直接解释行为 |

按适用性核对：默认、选中、禁用、只读、加载中、成功、失败、空内容、取消/返回、键盘/焦点。
有异步过程时说明开始/结束事件、反馈位置、能否重复/取消/离开。不要假定所有按钮都应禁用。
焦点位置、校验时机、返回后保留内容也必须有当前设计或观察依据，不能从通用指南直接抄答案。

### 2.1 大模块的布局与宽高适配

先按职责判断模块：承载页面主要内容区域、负责独立容器布局的工作区主内容、结果表/报表、
分栏，以及大型弹窗/抽屉属于本规则的候选对象。不能凭任意像素阈值判“大”，也不把每个卡片都算大模块。
这里的浏览器宽高指页面可用视口和模块可用空间，与浏览器品牌兼容是不同事项。

只有来源或实际观察证明，可用宽度或高度变化会影响该模块的布局、内容可见性、溢出/滚动策略，
或使模块连续伸缩、填满剩余空间时，才要求写清“布局”与“适配”。不要求一定跨越断点。
按钮、图标、单字段、装饰卡片等小控件仅继承父容器尺寸时，规则归父模块说明一次。
没有适配需求的条目不生成空段，也不生成“待确认是否适配”。

适用时，按现有 `details.visual` 文本写“布局：……／适配：……”，或放入适用的 UI 主要说明：

- 布局说明可用宽/高和占位关系，交代同级分栏、固定区域与滚动区域，以及哪些区域填满剩余空间。
- 适配只写有据且适用的变化：宽度不足时的换行、堆叠、收起或横向滚动；高度不足时的内容可达性、纵向滚动及固定操作区域；连续伸缩时哪些区域随可用空间变化。
- 断点、尺寸、最小宽高必须可追溯到确认规格或实际观察，观察值标“当前实现”。已确认、已观察、待定事项分别表达；只有实际适用且未定的具体取舍才写待确认。

不猜行业断点或最小尺寸，不擅自设计移动版；不新增数据字段、模板或每卡必填表单。
AI 仍只处理本次授权范围的适用行为，人工可在整份受支持原型编辑模块规则。

## 3. 通用术语

| 层次 | 约定 |
|---|---|
| 直接使用 | 按钮、输入框、复选框、下拉菜单、弹窗、抽屉、侧栏、标签页、校验、加载中、空状态、重试、滚动 |
| 必须区分 | 禁用＝暂不能操作；只读＝可查看但不能修改；悬停、焦点、选中各自描述，不能互换 |
| 首次需要时解释 | 防抖（停止输入后再执行）、乐观更新（先显示结果，失败再恢复）、骨架屏（内容加载前的占位）、模态弹窗（打开后暂不能操作背景） |
| 默认正文避免 | schema、payload、hydration、DOM selector、D/STATE/AC、LLM、token、置信度、tombstone、Agent、prompt、artifactRef |
| 删除空话 | “赋能”“无缝协同”“优雅降级”“丝滑闭环”“智能处理异常”不能独立充当行为说明 |

不堆 Toast/Popover/UE 等缩写。确有必要的工程依赖放折叠“开发补充”，且必须来自已确认工程约束；
不能擅自指定库、接口、事件总线或技术实现。机器字段、合并日志和模型生成过程不进入默认正文。

## 4. 五类轻量模板

以下方括号是待填写提示，**不是业务事实**。插入时只取适用句，删除不适用项；未解决的关键事项必须
保留为待确认，不把占位符当完整内容通过最终审阅。模板不预设尺寸、毫秒数、字数限制或接口。
表单只呈现本节简短提示及模板入口，不把整份规范塞进编辑器。

条件式提示（适用的列表、分栏、大型弹窗/抽屉及 UI 模块共用）：先按 §2.1 判断模块职责与有据的宽高变化。
确实适用才提示“写清可用空间、占位/固定/滚动区域及实际宽高变化”；小控件归父模块，不插入空布局/适配段。

### 4.1 操作按钮／提交

编辑提示：写清触发结果、处理中可做什么、成功和失败后的去向。

> [条件]时，点击“[操作名]”后，[可见反馈及状态变化]。
> 处理中，[是否允许重复操作、取消或离开]。
> 成功后，[更新内容及关闭/跳转/停留结果]。
> 失败时，[提示位置与问题]；[输入是否保留]，[修正或重试方式]。
> 原型暂未演示：[已定但未演示的分支]。待确认：[尚未决定事项]。

### 4.2 输入与校验

编辑提示：写清可输入内容、何时检查、错误出现与清除方式。

> “[字段名]”接受[有依据的输入条件]；[触发事件]时进行校验。
> 不符合条件时，在[位置]显示[有依据的文字或问题说明]，并[保留/处理输入]。
> [改正或再次校验条件]后，[错误清除与继续操作结果]。
> 键盘：[适用且已确认的行为]。待确认：[缺少的输入上限/规则等]。

### 4.3 列表／筛选

编辑提示：写清生效时机、保留条件、无结果及分页或滚动变化。

> [改变筛选/点击查询等事件]后，列表显示[明确匹配规则的结果]。
> [切换页面/返回]时，[筛选条件的保留规则]。
> 没有结果时，[显示内容与下一步]；[分页/滚动是否重置及依据]。
> 原型暂未演示：[未演示分支]。待确认：[未定事项]。

### 4.4 弹窗／抽屉

编辑提示：写清打开、关闭与取消的区别，以及背景和焦点行为。

> 点击“[入口]”打开[弹窗/抽屉名]，[初始内容及焦点位置]。
> 打开后，背景[是否可操作]；[适用的键盘范围]。
> 点击“[完成操作]”后，[结果]；点击“取消”或[其它关闭方式]后，[是否保留修改]。
> 关闭后，[返回上下文与焦点位置]。待确认：[尚未确认的关闭/焦点规则]。

### 4.5 UI／动效

编辑提示：写清触发、变化对象与结果；参数有来源才填写。

> [状态/操作]触发后，[对象]从[原状态]变为[目标状态]。
> [有依据的布局/显示/溢出/滚动规则]；参数依据：[确认规范或当前实现记录]。
> 中断或返回时，[结果]；减少动态效果时，[已确认的替代表现或待确认事项]。
> 原型暂未演示：[分支]。待确认：[缺少的尺寸、时间或状态规则]。

## 5. 正反例

以下均是**虚构的写法示例**，不构成任何项目的设计要求。

**不采用**：“用户触发提交事件后，系统基于异步状态机进行校验与幂等处理，以 Toast 完成闭环反馈，
300ms 内智能 persistence，失败自动优雅降级。”

问题：混入技术与生成词、无来源时长，没有说清显示什么、保存什么、失败后怎么办。

**可采用的表达**（假设这些行为已确认）：

> ③ 保存修改｜交互
>
> 点击“保存”后开始提交，提交期间不能再次点击。
> 保存成功后关闭弹窗，列表显示修改后的内容。
> 保存失败时保留已填写内容，在保存按钮上方显示错误，用户可再次提交。
> 原型暂未演示：保存失败。待确认：错误提示的具体文字。

另外四类的表达对照（同为假设示例）：

| 类别 | 不采用 | 可核对的表达 |
|---|---|---|
| 输入 | “输入自动智能校验” | “点击保存后，空字段下方显示必填提示；补齐并再次保存后清除提示。” |
| 列表 | “优化搜索体验” | “点击查询后更新结果列表。没有结果时保留筛选条件，并提供清空筛选入口。” |
| 弹窗 | “支持弹窗编辑与返回” | “点击取消后关闭弹窗并放弃本次修改；焦点回到原编辑按钮。” |
| UI/动效 | “以合适时长流畅展开” | “展开后显示完整说明，收起后保留标题。展开时长待确认；原型暂未演示减少动态效果的表现。” |

未确认这些规则时，应改为待确认或当前观察，不能因为套用了模板就断言它们成立。

大模块适配的表达对照（同为虚构示例；假设注明的观察确实存在）：

**可采用**：“当前原型：布局：页头和左侧导航占位，结果模块填满主工作区剩余的宽高；筛选区位于上方，表格内容在其下方滚动。适配：改变可用宽高时结果模块连续伸缩；高度不足时表格区纵向滚动，筛选区保持可达。”依据应链接到该布局和视口变化的实际观察；这段不推导未观察的窄屏堆叠或固定操作区。

**不采用**：“所有按钮和卡片：布局待确认；适配待确认。小于 768px 切换移动版。”问题是逐控件空段、无据断点与擅自设计移动版。
若保存按钮只是随父模块占位，写按钮行为即可，宽高规则归结果模块一次；若大模块没有有据的宽高变化，也不补适配段。

## 6. 呈现与内容审阅

默认显示标题、主要行为及必要例外；细节按需展开。“说明依据”和“开发补充”默认折叠。
差异使用“原型暂未演示”“与当前原型不一致”“待确认”。整体规则有稳定引用号，但没有假坐标或画面 pin。

自动检查能证明字段、版本、空内容、引用、重复编号及可确定的名称不一致；措辞和长度提示只提示。
人工修改不因语言检查被锁住，也不由 AI 自动改回。机器通过不代表自然语言准确。

独立 UX/前端审阅必须只凭实际说明、原始规则和原型，覆盖上述五类适用样本，回答：

1. 能否指出触发条件、可见结果、必要例外和返回方式？
2. 范围内行为清单是否全部有说明或设计师明确的待定处置？
3. 每个参数、确切文字、事实断言能否找到来源？观察与规范冲突是否显式保留？
4. 未演示与未决定是否分开？术语和模块名能否被同事准确复述？
5. 大模块是否按主要区域/独立容器职责判定？确有连续伸缩、剩余空间填充或布局/可见性/滚动变化的模块，是否写清布局与适配并给出来源？
6. 宽高说明能否定位可用空间、占位、固定区和滚动区，以及实际适用的宽度不足/高度不足处理？参数和观察值是否可追溯，是否误造断点或移动版？
7. 小控件是否归父模块统一说明，无需求是否避免空段？AI 覆盖是否仍限授权范围，人工全原型编辑是否保持？

关键业务规则缺失或冲突时回源解决，或由设计师明确按待定范围交付，不能凭“读起来顺畅”关闭门禁。
合成示例只验证模板表达；不能冒充 A-11 真实原型内容审阅、浏览器行为、真人试用或固定 UI 采用。

## 7. 研究依据及适用边界

本规范采用冻结研究 `framework-audit/2026-10-04-prototype-notes-research.md` §7 的 WR-01–05：
Carbon 的状态/操作分写，GOV.UK 的问题与改法及输入保留，Digital.gov 的读者导向和主动表达。
下列链接用于追溯 2026-10-04 已读取的来源，**不声称本文件生成时重新访问**：

- [Carbon Text input](https://www.carbondesignsystem.com/building-blocks/core/components/text-input/guidelines)：WR-01，区分状态与校验。
- [Carbon Modal](https://www.carbondesignsystem.com/building-blocks/core/components/modal/guidelines)：WR-02，分写触发、焦点、校验、关闭。
- [GOV.UK Error message](https://design-system.service.gov.uk/components/error-message/)：WR-03，问题、改法、输入保留与不可自行修复问题的区别。
- [GOV.UK Button](https://design-system.service.gov.uk/components/button/)：WR-04，动作结果与重复提交反馈。
- [Digital.gov plain language](https://digital.gov/guides/plain-language/principles)：WR-05，按读者知识组织、主动表达。

这些来源不是统一行业标准，也未替当前项目确定尺寸、焦点位置、禁用条件或校验时机。
本文件是适配后的交付写作合同；产品界面 voice/tone 仍由项目和已有 ux-writing/Brief 合同拥有。
