# 轻量竞品对照 — 由 agent 提议、按需才做

仅当 agent 要提出这次对照，或用户已说“看看竞品/对照一下”时完整读取；其余时候不加载。
这不是 skill、模式、审批或 Packet/TAC 字段；它只是一次**由用户决定要不要做**的参考材料。

## 1. 何时提议（命名决定测试）

只在能写出一句“本需求里【某个具体决定】，看别人怎么做可能改变它”时才提议；写不出就整句不出现，也不问。
不提议：机制已定且用户已给参考；只是修改已有页面、没有新机制；用户说了“不用研究/直接做”；
本任务已问过（同意或拒绝已记入来源索引，下游继承，不重问）；没有已锁定项目（NO_PIN）——此时不发起扫描，
只把候选对象留给用户日后作为材料。谁最先能命名这个决定谁问：brainstorm 在其 Optional additional research
块里（gap-finder 之后），否则 design-brief 在 Phase 0。

## 2. 怎么问（一次、开放、纯文本）

用本轮已有的入口句点明那个决定（这是用户要求的、只问一次的提议，复用入口句，不是另加的路由问卷），
并附 2–3 个由需求推出的候选对象，每个一句理由，标“凭已有认识、未核实”：

> 这条需求里【决定】可能参考别人的做法。要不要轻量看一眼？我想到：A（理由）、B（理由）、C（理由）——都未核实。
> 你可以删、换、补你想看的，或者说不用。

不出选项菜单，不问预算、深度、维度。“你定”＝接受我的候选（最多 3 个）；“不用”＝终局，本任务不再问。
候选规则：同一用户任务、角色和平台；至少一个机制与其余不同；用户点名的必含；不确定是否存在的写“待核实”，
不编造产品；没有固定候选池。用户已给的材料分三态：已成形的截图/录屏/分析 → 只摄取，不扫描；
给的是对象或链接并说“看看” → 视为同意，直接按下面的预算做，不再问；超过 3 个 → 按可比性取前 3，如实报“未覆盖”。

## 3. 怎么做（用户同意后）

执行体用现有 `quick-research`：一个后台执行者、一份短 markdown、逐条出处，沿用它自己的完成门，本文件不另加。
它自带固定开销（落盘到项目 `docs/research/`、完成门与 handoff 判断），所以这不是“一句话就完”的事；
用户说“看一眼”即同意本次读取这些公开页面（≤6 次），不需要另问网络许可。
本文件只给它题目和参数：≤3 个对象，整次 ≤6 次读取（用户给的链接也计入）；来源 = 竞品自家页面、文档、更新日志、
公开演示和用户提供的材料；评论/论坛只用来定位，不作结论依据；不写效果主张。

**证据天花板：** 该执行体只有 WebFetch/WebSearch，没有浏览器，所以得到的是**文档层先例**，不是看过真实界面；
视觉和交互行为只能记 UNVERIFIED。要看真实界面，请用户贴截图/录屏当材料，或改走 ux-research。

证据类型、出处、访问日期、版本、“采用不等于有效”和反证，一律沿用
[competitor-analysis.md](../ux-research/references/competitor-analysis.md) 的「观察与证据」，这里不复述。
本文件只新增一条：证据日期超过约 18 个月或版本不明，标 stale，不当作当前做法。
对象本身是 AI/Agent 功能时，观察面按 [ai-native-design-framework.md](ai-native-design-framework.md)
的 Layer C（信任）与 Layer D（代理）记录，同样只写已见事实。

输出形状：文件头写 `decision: <命名决定>` 与 `decision_changed: pending`；每个对象写已见事实（证据类型 + 日期）、
迁移判断（适合 / 不适合 / 需适配，一句）、对该决定的影响或“无增量”、未知项。没有增量就如实写，不强造差异。

## 4. 输出中性

结果是参考材料，不是需求：不新增 Packet/TAC 字段，不自动升 MUST，不进入任何生成输入；
只有用户在 Brief 里明确采用某条，才按 design-brief 现有规则落入 D/STATE/AC。它不改变 open-design / claude-design 的产出。

## 5. 记录与检验

同意、拒绝和文件路径记进既有来源索引（design-brief Phase 0 登记的“来源/确认状态/未决项”，brainstorm 的 Source Research），
不新增字段；Source Research 没有路径可写时（例如拒绝），用一行 `competitor-scan: declined` 备注，不改字段定义。
停止条件要能度量：提议的 agent 在每次提议结束时，把“日期 / 同意或拒绝 / decision_changed”追加一行到所在项目的
`docs/research/competitor-scan-log.md`，由用户在需要时核对。`decision_changed` 由用户当场的回答，或 Brief 中某条 D 的 rationale 引用本产物并写明采用/调整来判定，
不由 agent 自评。预先登记的停止条件：前 5 次真实提议里，被接受并执行的至少 3 次中 `decision_changed=yes` 不到 1 次，
或拒绝率超过 80%，则本文件回退为只保留 plan-design-guidance 里的一行，由用户裁决。

## 6. 边界

系统性、多维度的 UX 研究 → ux-research（沿用已选对象，不重问）。市场规模、定价、定位这类事实 →
deepresearch / quick-research 本体。本文件不新建 skill、模式或审批。
