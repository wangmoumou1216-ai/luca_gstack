# 设计系统与通用实现合同

> 共享 reference，保留既有文件名供 design-brief、HTML 生成器及评审按需引用。
> 本文件拥有范围、操作层级、一致性、可读性与改动追踪；具体视觉值和组件实现由当前项目或用户在外部工具配置的设计系统决定。
> 缺少外部规范时仍可交接需求、实现一般交互和评审一般 UX；规范合规结论标 UNKNOWN，不以本仓旧品牌或组件映射补空。

## 执行原则

1. 按已确认需求、设计决策、状态和修改范围实施。保留范围外区域与既定业务行为。
2. 页面参考默认提供结构和位置线索；采用参考不等于锁死其像素、布局或视觉。用户明确要求原位/不移动时单独记录约束。
3. 视觉值、组件库和资产来自当前项目已确认输入或外部设计系统。本文件不覆盖外部设置，不强制本地母版、token 表或技术映射。
4. 用户明确约束与当前规范冲突时记录冲突并解决；不得把未提供的设计规范说成已验证。

## 一、组件实现

依据实际实现平台和项目合同选择组件。区分组件入参、状态、事件与可访问性职责；将需求与交互位置追踪到既有稳定 ID。
技术组件名只属于实际实现合同，不成为需求交接前提。未经实现证据核对，不声称某 UI 已对应到指定组件库。

## 二、视觉来源

使用实际项目/外部设计系统的颜色、字体、间距及组件规范；记录可核验的来源与版本。
页面参考、截图或已产原型中的值是该产物的观察结果，不自动晋升为跨项目规范。
缺规范时根据已确认需求设计，并如实记录尚未确定的视觉细节；不得复制旧配色表作为默认方案。

## 三、文字层级与可读性

- 按内容需要区分主要信息、正文/字段值、标签/次要说明和辅助元数据。层级名称是语义，非固定字号档。
- 同级文本保持一致；标签与值可辨认，字段值容易扫读，主要信息能被快速找到。
- 根据当前规范用大小、字重、颜色和空间共同建立层级；次要文字仍须可读，不能通过降低对比度隐藏真实文字。
- KPI 等强调服务信息优先级，避免整页争抢焦点。实际字号、行高、字重由当前项目/设计系统决定。

## 四、间距与分组

用组内/组间距离表达相关性；同类卡片、字段、列表保持一致节奏，标签与输入框对齐。
具体间距服从当前规范和视口，避免无理由的随机差异；不采用本仓旧固定间距档作为通用门。

## 五、尺寸与滚动

按钮、输入框、表格、工具栏和分页区按目标平台与内容确定尺寸；验证文字不截断、目标可操作。
长内容可滚动且关键动作可达；区分视觉尺寸与实际命中区。具体高度和容器限制由当前项目决定。

## 六、操作层级、颜色与对比度

- 每个操作区域的主操作唯一；多个同等主操作争抢注意时重新分组，保留清楚的操作优先级。
- 次操作、文字操作和危险操作语义可辨；危险操作明确后果。成功、错误、警告、信息状态跨页面保持一致。
- 状态通过文字、图标或其他非颜色线索可识别，不能仅靠颜色传达；卡片与背景、控件与周围内容保持可辨认。
- 边框与阴影服务分组或浮层关系，按当前规范使用，避免无目的的重复装饰。

**对比度核验（承接旧品牌文件的通用行为）：** 对实际前景/背景组合测量并记录结果。
普通文字按 4.5:1、符合大字条件的文字按 3:1 检查；必要的控件边界、状态图形与焦点指示按适用非文本规则检查 3:1。
字段标签、时间戳和辅助说明仍是真实文字，不能用非文本门槛代替文字门槛。区分装饰、禁用与承载信息的元素；
注明项目适用标准及例外依据。没有实测组合或必要动态证据时写 UNKNOWN，不宣告合规。

亮色底配白字、浅色文字配浅底都需要实测，品牌指定值不自动豁免。失败时可保留背景并调整前景，
或调整背景并保留前景；按项目权限与规范选择，重新测量所有受影响状态，不能把另一配色的旧测量值当作本次证据。
暗色/其他主题分别验证；修复文字可读性时保留既有信息层级，不在全局母版上直接修改。

## 七、弹窗与操作可达性

保留清晰标题、任务内容和操作区。取消/返回与主操作可区分，内容滚动后仍能完成或退出任务；
按钮顺序、宽度和滚动布局按当前平台/设计系统决定。键盘、焦点、关闭与恢复行为须有实际验证，截图不能证明这些行为。

## 八、布局与修改边界

遵守用户已确认的修改/保留范围；涉及范围外区域或改变明确保留的布局约束时先取得相应决定。
默认保留已定业务结构和信息关系；参考页的顶栏、侧栏、卡片、Tab 与背景不自动成为必须复制的组件/视觉。
存在多方案尚未收敛时显式记录，实施或开发前确定本次采用方案。

## 九、图标与资产

按当前项目/外部设计系统使用资产。使用前核验资产真实存在且目标产物能够访问；找不到就记录缺口，不编造路径。
同用途的图标语义与风格保持一致；装饰图标与有操作含义的图标分别处理可访问名称。
使用本地资产也服从当前读取权限；framework/ 保持只读，不因引用本文件扩大目录遍历或写入范围。

## 十、改动追踪

- 只实施已确认需求和报告问题；新增范围须明确记录和对齐。
- 评审修复逐处使用 `<!-- FIX: {ISSUE_ID} -->` 或平台等义位置标注，关联原问题 ID。
- 保留需求→决策→状态→验收的稳定 ID 与来源；不重编或复用编号。
- 纯截图无法证明的交互、键盘、焦点和恢复行为标为未验证；不得用静态外观充抵行为验收。

## 十一、交付前自检清单

- [ ] 当前规范来源/版本已记录，缺规范时没有伪造合规结论？
- [ ] 文字层级、标签和值、主要操作及状态语义可辨且一致？
- [ ] 文字/控件/焦点的适用对比度已有实际证据或明确 UNKNOWN？
- [ ] 间距与分组一致，长内容、关键动作、目标视口均可用？
- [ ] 所有非 N/A 状态、退出/恢复路径与用户控制权均有对应实现？
- [ ] 每处修复有 FIX/ISSUE_ID 追踪，所有改动对应问题或已确认需求？
- [ ] 没有越出修改范围、伪造资产路径或覆盖外部设计系统？
