# 设计竞品分析 — UX 研究的条件方法

仅当用户要求设计竞品分析，或批准的问题涉及竞品页面、流程或状态时，在规划前完整读取。
这是 ux-research 的方法，不是独立 skill、必需上游或新研究模式。没有这类问题不加载。

## 范围与投入

最小输入是设计问题，可附链接、截图、录屏或原始需求；不要求 PRD 或 Workflow。
围绕同一用户任务、角色、平台及关键约束比较。目标任务不明时只补一个会改变范围的问题。
商业定位/定价分析归实际研究对象，不因“竞品”二字混入 UX 比较。

沿原深度与真实确认执行。focused 仍是一名研究者、1–3 个决策问题、整次 8 项检索/读取，
包含失败、重试和 examiner 要求的新检索；不会另开竞品预算。每个新页面/材料读取、
新增状态观察或新截图读取各计一项，批量逐项计；不得借浏览器免计。导航等实际工具、等待、
审查和下游消费记入真实成本报告，但不占这 8 项；已读材料只按其实际读取记录复用。deep/moderate 沿原预算与门。

选少量真正可比且机制有差异的对象；通常 2–3 个只是建议，不是配额。一个样本只支持该样本。
在原规划确认中合并说明问题、对象、材料和预算，已有真实选择不重问。
证据足够即止；预算到限且关键问题未知，保留缺口及下一次取证价值，不自动加深/扩量。

## 观察与证据

只展开与当前问题有关的面，其余一次简记 N/A 及理由；不能把未知写成不适用。

| 面 | 观察对象 | 能支持什么 |
|---|---|---|
| 结构与信息 | 入口、分区职责、分组、上下文保持 | 对应实际页面/状态的组织方式 |
| 视觉与内容 | 主次信息、主要动作、密度、可读性、文案 | 必须实际查看像素；仅文本不能声称视觉观察 |
| 操作流程 | 起点、动作、反馈、完成/取消/返回 | 实际操作/录屏或明确文档描述的行为，注明类型 |
| 状态与恢复 | 适用的加载/空/错误/部分完成、输入保持、重试/撤销 | 截图只证明可见状态，不证明未演示的转换；后者 UNKNOWN |
| 反馈与反例 | 针对同任务的用户反馈、失败情况及反证 | 有来源、有条件；未找到反证不等于无问题 |
| 迁移条件 | 角色、平台、频率、数据、权限及相关差异 | 哪些成立/不成立，什么仍需目标用户验证 |

每项观察给实际 URL/文件、页面/帧/位置、访问日期、平台/视口/状态与可知版本；未知版本不猜。
在现有 detail/evidence_basis 中区分直接观察、文档描述、推断、未知，不新增 schema 枚举。
产品采用某做法不等于有效；流行、官方演示、研究者模拟也不证明目标用户更快或更满意。
效果主张需要相应方法与人群证据。缺图/访问失败不能伪装完成视觉对照，可在原预算内改用
获准已有材料并限定结论；只阻断依赖缺失证据的主张，保留其余有据发现。
不为数量编造负面反馈；legacy 所需证据缺失如实记 gap，未满足的依赖不能 ready。

## 一份产物与下游

只写入既有 UX 报告的问题/D3 发现：紧凑同任务对照与现有 finding 引用；不追加报告或台账。
每个重要 finding/detail/design_signal 串接：原任务/未决点 → 观察及证据类型 → 可比性与限制 →
影响的决定及能/不能支持什么 → 待验证结果。研究不给用户代选方案。

原独立 examiner 复用本 owner，检查可比性、实际证据、观察到效果的越级、关键状态遗漏；
不增加第二轮日常专家会。缺原独立审查仍 BLOCKED，不以完整报告代 PASS。

ux-brainstorm 对影响当前方案的发现，在原理由中说明采用/调整/放弃/暂缓及理由，比较原方案、
迁移条件、预期收益、代价和翻转条件；把实际所选机制写入主任务走读和关键恢复。
目标/机制已定可直接进 design-brief，其来源索引核实际采纳，落入 D/STATE/语义位置/AC/Packet。
视觉观察通常转为信息优先级、可辨识性、上下文保持等要求；不自动规定组件或变成 MUST。
原用户约束冲突回交受影响决定，真实人类门保留。standalone 可交研究后结束，不自动启动下游。

区分改变设计的可验证贡献、支持保留/具名风险判断、无当前增量、未知。原需求已有要求或
直接 Brief/C0 已具备的收益不能冒领为研究增益；没有有用信息允许停止，不强造 UI 差异。
最终交互增益要由实际产物与同条件对照验证，报告、引用及字段齐全不证明改善。
