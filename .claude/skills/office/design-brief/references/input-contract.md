# Design input contract — 来源、继承与精修

本文件拥有 Brief 输入归一化及交付成熟度规则。模板语义/动作合同由 page-context 拥有，
Packet 结构由 output-templates/carrier-packet 拥有；这里不重复维护模板库或运输授权。

## 1. 来源登记（Phase 0）

| 字段 | 必填内容 |
|---|---|
| entry | pipeline / existing_requirements / prototype_visual_refinement |
| delivery_mode | traceable_delivery / design_generation / standalone_light |
| source | 实际文档/用户消息/原型节点或路径，版本与读取/观察证据；无法访问写原因 |
| intent | 用户、核心任务、对象、动作、可观察成功标准 |
| scope | 平台，整页/局部，修改区、保持区、明确不做什么 |
| template_intent | 用户已选模板/区域及原话，或未选/不用；具体ID/源hash在旁车 |
| freedom | 可变、不可变、须先确认三列 |
| gaps | 已确认、已观察、推断、未知；关键/非关键，所需最小补充 |

自然语言归一化链：用户原话→任务/对象/动作→区域职责→修改/保持→验收。
保留原话和意图的关系；“这个/那里/右边/处理区”必须有现有上下文或实际模板证据，
不能凭转写错误猜实体。复述核对只针对真实歧义，不让用户逐条重复清楚的需求。
只有实际逐字文本可标“完整原话”；转译/归一化摘要须标明，不能补成不存在的引语。
仅美化不授权植入：无明确嵌入来源时，不把add/modify提升为MUST；用户明确要求植入再美化时，
保留两项意图，分别核结构与精修合同的能力，不能混用同一执行profile。

来源索引按完整事实分解：
| ID | 精确来源/原文 | 类型 | 依据状态 | 本轮级别/范围 | D/STATE/位置 | AC/下游 | 结果 |
|---|---|---|---|---|---|---|---|
| REQ-001 | 消息/文档/节点 + 完整诉求 | requirement | confirmed/observed/assumption/unknown | MUST/SUPPORTING/DEFERRED | 引用 | Given/When/Then | MAPPED/... |

已有 ID 不改；REQ-/AC-/SRC- 是 Brief 本轮来源 ID，不代表 PRD R/AE。
用户明确要求照此实现/保留的输入为确认范围，不能为凑门禁再问一次“是否认可需求”。
用户未确认的模型推断不升级 MUST。原型已观察事实与用户要求保留的事实分开，记录两者关系。
输出AC可由明确需求推导并标“本轮验收表达”，不得增加新产品行为；新行为须先确认。
冻结前逐个核对正文、D、状态、AC与Packet里的可执行动作名及条件：每项须有当前来源或明确授权的推导；
通用模板中的搜索/详情/返回等示例不能因斜线并列而变成本轮事实，其他场景的动作也不能迁入。
无来源项删除或仅列为未决问题，不进入执行正文；被排除备选须标本轮分析，不冒称历史决定。

## 2. 三入口的最小工作

pipeline：读取明确选择的 PRD、方案及相应 handoff；继承 AI 判定/假设/否决/Oracle修正/
voice-spec 语义，核交互粒度与适配冲突。研究只有被已选方案/PRD引用时进入设计约束。
existing_requirements：忠实整理原话、补齐交互/状态/AC；不要求 research、PRD 或两份方案。
机制已定则设计收敛；多方案未选/核心机制不明才回相应发散节点，不由材料名称强制整链。
prototype_visual_refinement：读取原型实际内容/路径与用户精修意图，做行为提取/保持和模板适配，
不把“UI美化”理解为重做UX。原型是观察/来源证据，Brief 是执行事实 owner。

traceable_delivery = 实际 PRD 全链追踪；design_generation = 当前设计源完整追踪。
二者都可形成完整 Packet，后者不能进入工程链冒充 PRD。standalone_light 是文档未决/有限模式，
保留 LIMITED，不能规避关键缺口并宣称“已经可生成”。

## 3. 原型保持合同

| 面 | 提取并保留 | 缺口处理 |
|---|---|---|
| 流程 | 起点、动作、分支、导航、完成/取消/返回 | 仅截图不能证明分支；关键未知问操作或说明 |
| 数据 | 字段含义、输入/输出、关联/顺序、单位、校验语义 | 占位数据不是业务规则；不推断接口/真实数据 |
| 权限 | 可见/可操作/禁用及授权条件 | 未演示角色不宣称已验证 |
| 状态 | 触发、反馈、输入保持、重试/撤销/恢复 | 关键缺态补齐确认，非关键未知写明待验 |
| 范围 | 原型模块、模板承载职责、保持区与允许视觉变化 | 模板不适配不能静默删原型能力 |

自由度三列示例：
- 可变：已授权区域的视觉层级、排版、颜色、间距、图标表达，遵守实际工具 DS。
- 不可变：确认的用户任务、字段含义、流程分支、关键动作/权限/状态、明确保持区。
- 须确认：新动作/删除动作、信息优先级影响任务、入口迁移、合并步骤或改变字段/校验。
视觉改善影响可访问性或行为时不自动算“可变”。发现原型问题，记录风险与建议，由用户裁定范围。

精修与嵌入分开：已有模块视觉改动为 refine；新增/替换原型内容为 add/modify。
两者都被明确授权时，按阶段分别写可变/不可变/须确认：结构阶段只允许已授权植入的结构范围，
精修阶段才是仅视觉变化。不得用全包“只可改视觉”否定植入MUST，也不得因植入授权扩展精修范围。
初版 refine 只允许 refine + preserve，真实节点内 class/style 有效变化；业务 DOM/行为属性/
脚本/全局CSS/资产保持，禁止冒充空格修改。需要结构与样式混合或新增行为时返回原范围确认，
不自动扩大 refine。静态carrier精修另要求可判定子集中的有效inline CSS声明变化（class-only拒绝）；同一变更style内原样未知声明仅豁免font-family/box-shadow，其余未知声明默认可能覆盖并拒绝。原件用inert浏览器检查合法声明/类token，两者都不证明实际像素/行为。原件与 static carrier 使用各自适配器，不改变原件资格字段绕过安全。

## 4. 模板与执行能力冲突

| 情况 | 处理 |
|---|---|
| 用户已指定模板/位置且证据有效 | 直接继承，不另推荐替代 |
| 同义口述但职责清晰 | 用实际语义与源定位，说明来源，不要求逐字名称 |
| 同用途两个位置 | 只问区分两者职责的一个问题，等待真实答案 |
| 没有内部候选 | NO_HINT，仍检查用户指定源/完整目录；无模板则继续语义契约 |
| 必要状态/动作未知或不支持 | 列证据/影响及换模板、明确扩展、改变范围选项；保留全部源事实 |
| 仅 connector 不支持 | 契约可保存，执行 BLOCKED；不伪造执行/保真/上传证据 |

草稿与正文可以在冻结前迭代；正式 binding/TAC只在冻结后指向完整事实。
模板选择确认与 bundle采用不同；有效选择可重用，不能让用户重述，但新bundle不能伪造确认。

## 5. 生成与验收

每条本轮 MUST 来源、D、适用 STATE、保持项都有语义位置、下游与 Given/When/Then AC。
精修验收含：原型前后行为/数据/权限/状态对照、授权区视觉质量、保持区范围、键盘与焦点、
状态消息可感知、目标视口任务可完成。机械 PASS 与视觉/交互/语义 PASS 分开记录。

运输原型证据为实际bytes + MIME + purpose + 既有source_ids + hash，置入完整immutable inventory；
附件不是第二需求事实源，不自动执行HTML，不以本机路径代替可达文件。行为约束已在Packet完整表达。
生成目标能力未实测时只能交付契约/导出/置入相应状态，不声称生成完成或跨harness parity。

## 6. 可判定完成

来源继承、语义适配、状态/动作完整、精修保持、来源覆盖、冻结一致性逐项有证据。
关键未决→NEEDS_CONTEXT；工具/适配器不可执行→BLOCKED；完整设计源追踪→DONE，
但工程 ready 只在实际PRD追踪通过时成立。未验证非关键风险→DONE_WITH_CONCERNS并列具体影响。
