# Tracker Contract — 目标、映射与效果

在解析标签、discovery、override 或拟操作前完整读取。它是 issue-triage 的 tracker 消费合同，
不是第二份全局配置。使用用户提供或已授权项目现有约定；无接入仍可离线分析。

## 1. 当前任务绑定

记录以下字段及其真实来源，不按 remote/目录名猜：

| 字段 | 必须明确的值 |
|---|---|
| target | 已有 tracker 类型、已认证集成、精确 repo/project/workspace 与 item ID 解析规则 |
| material_source | API/connector 或离线 body/comments/labels/diff 的来源、读取时间、分页/缺页限制 |
| roles | 两 category、五 state 的 role→实际既有 label 映射、来源路径/用户答复及作用目标 |
| version | connector 支持的真实 expected version/token；PR diff 的 head revision 另记 |
| capabilities | read、条件写标签/状态/关闭、comment/readback/idempotency 各自可用性；不推测 CAS |
| external_pr_authors | 项目已确认的 internal/collaborator 集合或 external 判定规则及来源；仅 discovery 使用 |
| scope | 可读代码/词汇/ADR、已授权 `.out-of-scope/` owner 和精确文件写权、原 U-ID/resume_target |
| effects | 分别列已批/未批的 state、comment/send、close、KB/file 操作及真人授权证据 |

不自动认证、安装 gh/glab、建立标签或根 AGENTS/CLAUDE/领域布局。缺 target 只在现有材料内预览；
裸编号歧义需真实确认。缺 external 作者规则只列确认过的外部 PR，并标 discovery 不完整；
不能擅自把内部 PR 算外部或漏掉用户点名的内部 PR。

## 2. Canonical roles 与真实标签

| 类别 | Role | 含义 |
|---|---|---|
| category | bug | 行为损坏/违背既有合同 |
| category | enhancement | 新能力或改进 |
| state | needs-triage | 维护者尚需评估 |
| state | needs-info | 等待 reporter 提供具体信息 |
| state | ready-for-agent | 已有完整 brief，可交 agent；PR 指现有 diff 的下一步 |
| state | ready-for-human | 需要人类实施/判断；PR 可以是等待人工合并 |
| state | wontfix | 本次不行动，具体原因见 outcomes |

把每 role 映到目标中真实存在且已确认的 label 字符串，canonical 名称不必是 label 名。
缺映射输出 role+预览并询问既有 label；映射与项目约定冲突、一个 label 同时代表不同 roles、
item 有多 category/state 时，先指出并等维护者确认。不能在冲突下偷偷覆盖。
每个完成 triage 的 item 恰一 category 和一 state；保留所有不属于这两个映射集合的 labels。
拟操作展示旧/新完整 label set；使用支持原子条件更新的接口保住角色排他性，不能把先删再加
的无条件调用伪称 CAS。若 connector 无对应条件写，输出预览和精确人工动作。

## 3. Normal transitions 与 override

```text
unlabelled -> needs-triage
needs-triage -> needs-info | ready-for-agent | ready-for-human | wontfix
needs-info -- reporter activity after last triage notes --> needs-triage
```

needs-info 的新回应是回到评估的条件，不是自动 ready。readback 后识别有无 reporter 新活动；
旧答案进入已解决事实，新问题才询问。维护者可以 override 任何状态；异常转换先指出具体
from/to 与原因，待明确确认，不能把推荐或沉默当 override。已明确说明的 override 本身不重复
问其方向；仍解决冲突和精确效果范围。override 跳过 grilling，ready-for-agent 缺 brief 时问是否补写，
不暗中添加 comment/close。只有 role 获批时只处理该 role，其他效果保持未执行。

## 4. 预览、条件写与发送门

先读取并保存 item preimage：target/ID、version、labels/state/open-closed、body/现有 notes/brief、
comment IDs/markers；PR 附真实 head/diff 摘要。每项拟效果列 exact target、old/new、expected version、
权限来源和可检查 postcondition。新 label set、完整 comment、close 原因和 KB 精确 patch 均可审阅。

状态、labels 或 close 的覆盖必须使用 connector 的**真正 conditional write + expected version**。
read-before-write 后无条件更新不算条件写。接口不支持则保留 preview/手动动作，不假装修改已完成。
version/head 漂移时重新读取、核对 claim/决定并给新预览；实质变化重新取得所需授权，不覆盖别人改动。

comment、issue posting、close 和其他 send 都需要明确真人授权到具体 target 与完整内容/动作。
维护者选择 item、接受 category/state 推荐、完成 grilling 或批准 KB 文件写入不授权外发。
有效的既有精确授权继续生效，无需重复索取。每个外发 comment/issue 的最开头必须是：

```markdown
> *This was generated by AI during triage.*

<!-- issue-triage:<unique-operation-id> -->
```

operation ID 在一次逻辑发送前固定并记录；重读同一操作不更换 marker。支持时使用相同 idempotency key。
发送后读回 marker、comment ID 和完整 body；role/close 读回 version、完整 labels 与状态。
本技能不合并 PR、执行其实现、自动 reopen、发消息给其他人或创建 ticket。

## 5. Unknown、部分成功与恢复

分别记录 tracker 和 KB/file 的 pre/postimages、命令/connector 结果、readback 与实际 effects。
文件记录 exact path、type/mode/hash 及实际字节；tracker 记录真实版本/label set/comment ID/body/状态。
审计中脱敏秘密，不把 token 当公开示例。操作状态用 PREVIEW、APPLIED_AND_VERIFIED、FAILED、
EFFECT_UNKNOWN 等明确区分，不用一次整体 success 掩盖多个结果。

- Timeout/unknown：先 readback 查 marker/状态/postimage；存在即记录真实成功，不能重发。
  无可靠读回仍是 EFFECT_UNKNOWN，停止效果阶段；确认未应用并重新满足授权/CAS 后才可考虑重试。
- 有部分成功：保留已成功动作，列出失败/未知项及恢复点，停止后续效果。tracker 与 KB 没有
  跨资源原子事务；不能假装全成功、自动回滚、重复评论或关闭请求后宣称 KB 已完成。
- 恢复：读回最新版本、comments/marker、KB 文件及真实效果回执，从未完成项继续；
  preimage 或 scope 漂移就停止对应修改，不能把旧预览重放覆盖新内容。
