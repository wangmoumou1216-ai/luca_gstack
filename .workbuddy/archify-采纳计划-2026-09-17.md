## 3. 落位方案

### 3.1 安装位（**修正：不得落框架树**）

> 红队初稿建议的 `luca_gstack/skills/external/` 违反你的两条红线（framework 只读 + 产出物不落框架树），已纠正为**用户级受控路径**。

| 环境 | install_path | 说明 |
|---|---|---|
| Codex（主力） | `~/.agents/skills/archify` | 与 tdd / systematic-debugging 同约定 |
| Claude（辅） | `~/.claude/skills/archify` | 双 runtime 一致性 |

**拒 npx 路线**：`npx skills add` 全局路径不可控、无固定 checkout，会使 `installed-pins.yaml` 的 `watch_sha` 巡检失明 —— 这是决定的理由，而非仪式感。

### 3.2 安装动作（今天可执行）

```bash
SHA=72c750bb070d95171dbb2244e5b62b1b7da69c12
curl -sL "https://raw.githubusercontent.com/tt-a1i/archify/main/archify.zip" -o /tmp/archify.zip
# 校验：sha256 == d2296515b0091fb8f00580ea9e0b665d91ca5839fde651abe3ecd57a3ca178ec
shasum -a 256 /tmp/archify.zip
unzip -q /tmp/archify.zip -d /tmp/archify_extract
mkdir -p ~/.agents/skills ~/.claude/skills
cp -R /tmp/archify_extract/archify ~/.agents/skills/archify
cp -R /tmp/archify_extract/archify ~/.claude/skills/archify
```

### 3.3 护栏就位

```bash
# 1) 关闭每会话外联版本检查（写进 shell profile）
export ARCHIFY_UPDATE_CHECK_DISABLED=1

# 2) 移除更新检查脚本在自动化路径上的可调用性
chmod -x ~/.agents/skills/archify/scripts/check-update.mjs

# 3) 版本锁定登记备查
echo "$SHA" > ~/.agents/skills/archify/.luca-pinned-sha
```

### 3.4 验真命令

```bash
cd ~/.agents/skills/archify
chmod +x bin/archify.mjs
ARCHIFY_UPDATE_CHECK_DISABLED=1 node bin/archify.mjs doctor   # 期望：全 ok + "Archify is ready."
```

## 4. 触发设计（窄复合词条家法）

**收**（动作锚定复合词，不含裸词）：
`画架构图` `出架构图` `生成架构图` `系统架构图` `画流程图` `时序图` `数据流图` `状态机图` `生命周期图` `架构前后对比` `用archify` `archify`

**拒**（及其否决理由）：

| 拒收词 | 撞谁 / 为什么 |
|---|---|
| 裸 `图` `图表` | 撞内置 dataviz（数据图表），且违反裸词家法 |
| 裸 `架构` `架构设计` | codebase-design 已刻意不收此裸词，防劫持产品/UX 设计管线 |
| `可视化` | 太泛，会劫持数据图表与 UI 语义 |
| 裸 `状态` | 历史上已因业务语义误撞而撤（"订单状态页"） |
| `原型` `线框` `HTML` | 归属 html-prototype / open-design |

**路由层级**：`skill-routing-map.yaml` 尾部「外部 engineering skills」段，weight **7**（与 tdd、systematic-debugging 同级），`hint` 注明建议而非强制，条目注释写明 `sunset: 2026-10-17`。

**Plan Agent 关系**：画一张图产出 ≤2 文件、无 subagent、无阶段依赖、可逆 → Plan Agent 5 条件全不满足 → SINGLE_SKILL 直达，不浪费规划一次。仅复合诉求（如「读懂这个仓库再画架构」= code-recon + archify）才升 MULTI。

**是否进 workflow-graph**：**不进**。该文件自身原则为「does not own standalone skill execution」，它是独立交付物生产者而非管线阶段。tech-spec / code-recon / handoff 三处对其产出的消费，留作各自 SKILL.md 可改区的 enforced internal dispatch，待使用量证明后再议。

## 5. 日落条款（核心：默认动作自动发生）

- **借用期**：2026-09-17 → **2026-10-17**（30 天）
- **判定于到期日机械复算，不靠主观感觉**：

| 判据 | 门槛 | 复算方式 |
|---|---|---|
| 路由真实命中 | ≥ 3 次 | grep Codex/Claude 会话日志：含上述触发词且实际进入本 skill |
| 存活产物 | ≥ 3 个 `.html` | `ls -1 ~/Desktop/项目/*/docs/**/*.html .workbuddy/**/*.html` 计数（剔除本次实证样例） |
| 被文档引用 | ≥ 1 处 | 至少 1 份 md 内含指向该产物的相对链接 |

- **默认动作（自动执行，不是"再讨论一次"）**：
  - **达标** → 自动转正：移 sunset、计⼊ w7 正式段、补 `installed-pins.yaml` / `vetting-registry.yaml` / `INTEGRATION-MAP.md` 三处登记，写 tag+sha+ziphash
  - **未达标** → 自动卸载：`rm -rf` 两份 install_path + 移除 routing-map 条目 + 移除 profile 环境变量，并落一条治理动议「archify 未达准入线，已按日落条款卸载」

> 若届时三项判据任一项不可复算（无日志留存），视为未达标 ——举证责任在工具一侧，不在人一侧。

## 7. 两个失败模式与对冲

| 失败模式 | 表现 | 对冲 |
|---|---|---|
| **FM1 休眠 / 自证预言** | 触发词太窄，30 天零命中 → 得出「不需要」的假结论 | 触发词必须显式覆盖 5 类图语义（不只是"架构图"）；借用期内遇到审查报告、框架演进、handoff 三类任务时**强制试用一次**并留痕；此即"入侵式试运行"，是被否掉的被动试点的唯一解药 |
| **FM2 分发失控** | 外联复活 / zip 被换 / 版本跳跃 | 第 1、2 条护栏 + 到期日必查一次 sha256 复 anchor |
