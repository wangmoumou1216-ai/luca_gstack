## 一、需求

OD 产出的交付 HTML，目前缺交互逻辑说明。要求：

1. HTML 带一个**侧边栏**，写交互逻辑说明文案
2. **AI 能写、人能改**
3. 每条说明对应页面某个功能点，用 **badge 编号锚定**（页面上标 ①，侧边栏对应「1 - 交互说明」）
4. badge 支持**新增、删除、显示/隐藏**

## 二、交付出来长什么样

- 双击打开 index.html：右侧多一个说明侧边栏，页面上交互点挂着小数字徽标，点徽标 ↔ 侧边栏条目一一对应
- 右上角总开关：一键关掉，回到纯设计稿（URL 加 `?notes=off` 同效）
- 说明数据就存在这个 HTML 文件里面（单文件交付，发谁都能打开）

## 三、方案（大白话版）

**什么时候加**：OD 生成完 → 你说「拉回来」落盘后 → 你再说一句「给这个原型加交互说明」→ agent 注入。不说就不加，现有流程零变化。

**加的是什么**：往 index.html 尾部追加一个注释区块（说明数据 JSON）+ 一个小脚本（渲染侧边栏和 badge）。设计本体一个字不动。

**谁怎么改说明**：

| 动作 | 怎么做 |
|---|---|
| 改文案（对话） | 跟 agent 说「把 3 号说明改成 XXX」 |
| 改文案（手写） | 浏览器侧栏点「编辑」直接改 → 点「复制改动 JSON」→ 贴回会话说「合并」→ agent 校验落盘 |
| 新增 badge | 「给筛选区加一条交互说明」 |
| 删除/隐藏 | 「删掉 2 号」/「把 2 号隐藏」 |

手写改的安全规则：浏览器里的修改只是**草稿**（标「未落盘」），永远不自动写文件；贴回合并经 agent 校验后才成真值，文件内容恒赢，冲突时有横幅提示。

**OD 迭代后说明会不会丢**：不会。你在 OD 改完再「拉回来」，agent 出一份对照清单（哪些锚点还准、哪些飘了），你确认后重新贴上。

## 四、三个关键决策（为什么这么设计，一句话版）

1. **说明的「概念定义」放 prototype-spec.md，不塞进 HTML** —— OD 迭代后 agent 只做比对重定位、不自动重生概念，保 predictability（红队裁的）
2. **编辑双轨：对话（增删/显隐）+ 浏览器手写文案** —— 会审原判「浏览器编辑回路没人用」降为 M2；你确认会高频手写说明后提前进 M1，用「草稿+复制合并+revision 冲突保护」把风险锁住
3. **交付默认显示说明层，外发客户一键剥干净版** —— 默认关掉直接违背「交付带说明」的初衷（红队裁的）

**验收六判据**：可达性、注入零 diff、样式红绿灯、迭代迁移、门禁生效、**回归烟测**（改的是高频主力 skill，必测）。全绿才算落地。
**回滚有路**：开工前建 git 基线，不满意整体 revert；已注入原型可批量剥除（执行方案 §10）。
**每次使用的量级**：薄壳 + reference 约 3-4k token 上下文，注入一次对话内完成。

## 六、分期与边界

- **M1（先做）**：注入侧边栏 + badge + 总开关；双轨编辑（对话增删改 + 浏览器手写文案）；迭代重锚定
- **M2（后做）**：侧栏内直接增删 badge（锚点拾取器）、指纹自动重定位、精细视觉打磨
- **外部依赖脆弱点（已声明）**：锚定策略假设 OD 产物无语义 DOM；若 OD 未来产出带语义标注，锚定策略须重评

## 七、五条红线

1. 说明的「概念定义」唯一真值在 prototype-spec.md，agent 只做比对确认，不擅自重生
2. 注入区块外零字节改动；带说明的 index.html 是唯一真值，外发客户走 strip 剥出 `index.clean.html`
3. badge 用中性色（不用品牌橙），一个 badge = 一个「不看说明会误解行为」的点，单页 ≤5
4. 不伪装 traceability：决策卡回链是 best-effort，允许为空
5. 浏览器手写的修改只是草稿，永不自动写文件；落盘唯一通道 = 贴回会话经 agent 校验合并

## 八、额外价值（会审发现的复用面）

IA-NOTES 区块（注释定界 + JSON + runtime）其实是**仓库级微约定**——不限于 OD 链，未来客户交付物、其他生成器产物、教学演示都能复用同一套注解层。
