## 二、关键辩证记录（为什么改判）

### F1 为何是「MAJOR 弱」而非首轮的 MAJOR、也非校准官主张的 MINOR

- **校准官的降级理由被辩证 R1 逐条推翻**：
  - 「与被撤销的降级链项同构」——**不成立**。降级链是事后行为（fable 报错→自然降，无受害面）；白名单是事前判断（不该传的传了，无痕迹越权）。两者不同构，首轮内部不一致的指控瓦解。
  - 「yaml:177 宪法豁免低频事件不加 hook」——**张冠李戴**。该豁免原文限定「新增场景是低频事件」（新 skill/agent 定档评估），而 dispatch 是每次 spawn 的高频行为，且 dispatch_rules:100 白纸黑字自称「起为强制，非建议」。低频豁免罩不住高频强制。
  - 「AI 是合作方」——**本仓是信任但验证文化**：daily_governance 机检 luca 本人改动、verify-codex-wiring:161 把「自证式门禁不是门禁」钉进脚本。合作方≠免检。
- **但降半级成立**：审计管道半存在（PostToolUse 已含 Task/Agent，settings.json:53），缺的只是 model 参数校验+落盘这最后一公里；修复成本一行式。
- **定性改写**（替代首轮「违反自证先例」措辞）：`dispatch_rules:100 自称强制却检查侧零落点——连自证式门禁都未建立`，比先例语境更严一级但缺口更小。

### F4 为何从 MAJOR 大幅下调

- **不是安全漏洞**：writable_roots 含仓库是 2026-08-06 的**功能必需配置**（缺它 MEMORY_ROOT 记忆写入全断，实证 PermissionError），写入行为有意。
- **是过时宣称**：AGENTS.md:375-379 的「仓库写入被沙箱硬拦」出自 08-05 红队裁决，08-06 配置加入 writable_roots 后被静默作废，宣称未随配置更新。config.toml:39「仓库…无需列出」与 L45 实列是同源自供矛盾。
- **但残留真实风险**：Discover phase 把外部 GitHub README 拉进 agent prompt（injection 入口真实），「硬拦」宣称若被未来设计者当真，会错误放宽 prompt 层防护——故定 MINOR 偏下而非纯措辞级。

### 二阶复核的新增贡献

1. **PostToolUse matcher 已含 Task/Agent**（首轮只查了 PreToolUse）——F1 修复的接线点已存在。
2. **evals 档位盲区**（F9）：执法（F1）与度量（F9）两面皆空，完整化了「档位层无验证」的图景。
3. **撤销项追溯**：恢复 D2 为 F3 附注，消除一个「豁免条款扩张解释」掩盖的 parity 不对等。
4. **F4 修复位置清单扩容**：不止 AGENTS.md 与 runner 两处——test-workflow-runner.mjs:78 注释与 W4b 断言标签「仓库不在可写面内」是同源错宣称，**共 5 处需修正**。

## 三、最终修复优先序（经辩证 R2 裁定 + R3 校验）

1. **F2（S8d 断言）**：verify-codex-wiring.mjs 加 S8d——单向包含断言（yaml codex.tier_to_effort ⊆ runner TIER_TO_EFFORT + PHASE_TIER 值域 ⊆ tier 名集合）。纯静态文件比对、无订阅依赖、verify.sh S34 路径即达。**不用逐值相等**（会误伤 runner 未来加降级链——runner 当前无 fallback，模型不可用直接 done(null)，与 yaml Claude 侧 fallback: opus 不对称）。
2. **F1（PreToolUse Task matcher）**：加 Task/Agent 进 PreToolUse matcher，hook 校验 `tool_input.model ∈ 合法别名集`并落盘审计 jsonl。**两个必要语义**：model 缺省须放行（继承主循环是 yaml:105 合法路径）；hook 只能校验别名集、无法判定白名单场景（场景判断仍靠纪律——这正是「机械兜底+纪律主路径」的正确分工，与 yaml:177 哲学自洽）。技术可行性已核验：project-scope-guard.mjs:29,71-72 证实 stdin 含完整 tool_input、model 字段可见。
3. **F3（Codex P0 升档 + 附注）**：yaml codex 段补「P0 场景 effort 升 xhigh」规则、quality-gate 调用方合同写明 `-c model_reasoning_effort` 覆盖通道、workflow 定档行为入档（PHASE_TIER+fallback 语义写进契约）。跨 harness 行为对齐，成本最高，垫后。
4. **F9+F4（杂项班车）**：fixture 加 expected_tier 字段一行断言；5 处过时宣称统一改写（AGENTS.md:375-379 → 「默认拦+显式白名单放行」、runner:93/255-258、test-workflow-runner.mjs:78+W4b 标签）。**writable_roots 本身不动**（动了重造记忆断裂事故）。
5. **F5-F8（措辞统一）**：枚举口径按 harness 分册各定全集（模型侧拒绝 minimal、config 层合法，补漏 max）；yaml:128 示意改用现行值。
