## 一、需求底层逻辑：这套系统为什么存在

### 1.1 三句话本质

1. **配额经济学**：fable 配额稀缺昂贵，而高杠杆判定（出门前裁决/对抗/翻案复审）不能降档——系统的存在根源是把最贵模型精确滴灌到「单次 5-30k token、判断杠杆极高」的点位（yaml:40-42 评估维度：token 量级 × 判断杠杆 × 错判代价）。
2. **以相对序换零维护**：以「能力档相对序」为不变量（Claude 侧 fable>opus>sonnet>haiku；Codex 侧 xhigh>high>medium>low），换取模型换代、订阅失效、跨 harness 三种环境剧变下的零维护——档内升级（Opus 4.7→4.8）自动跟随，档位语义不丢（yaml:126-129）。
3. **代价**：路由正确性至今主要靠 prose 纪律而非机检——全部 MAJOR 级发现都是「自称强制的规则缺检查侧落点」型缺口（见 §四）。

### 1.3 治理哲学边界（本仓宪法）

- **宪法总纲**：机检管静态一致性、纪律管创建时定档；凡自称强制的规则必须在检查侧有落点，否则降级为建议。框架本身只读（MEMORY.md 红线 / CONTEXT.md SF-002）——本报告全部为待 luca 裁决的动议，不执行。
- **机检面**：每日 governance、S8b/S8c、tripwire 扫未定档场景。「检测自动化，重映射判断留给人」（yaml:11-12）。
- **纪律面**：创建时定档；「拿不准就选更强档；档位变更须用户批准」（AGENTS.md:428）。用户控制权（/model 主权、白名单批准制、native_precedence 让位条款）是下位原则。

## 五、锚点制动态模型调配方案（v2.0 核心新增，luca 14:07-15:11 点名）

> 完整推导与对抗过程见《锚点制动态调配设计稿 v2.2》（同目录）。本节为裁决后的执行摘要。

### 5.1 峰值三明治（核心模式，多峰循环）

```
计划(peak) → 执行(anchor) → 验证(peak) ⟲（否决→重规划(peak)→再执行→再验证）
```

- luca 原话锚点："开始计划和结果验证需要高模型"
- **这不是单 pass 三明治，是多峰循环**（专家A）
- 正是 fable_whitelist P0/P1/P2 在 Codex 侧的缺失投影（= F3 的修复）

### 5.2 两角色制 + ARR 动态兼容（模型第一公民，无 effort 轴）

| 角色 | 解析规则 | 当前实例 |
|---|---|---|---|
| **anchor** | config 顶层 `model =` 行（luca 随时改，唯一 truth） | gpt-5.6-sol |
| **peak** | catalog `priority` 最小值（家族顶部），规则解析 | gpt-6-astra (priority=0, ctx 1.05M) |

catalog 实测（13 模型）：astra(p0) < sol(p1) < terra(p2) < luna/reserve(p3) < 5.5(p7) < 5.4(p16) < mini(p23) < spark(p26) < 外家族(1004+)。

**ARR 锚点动态兼容方案（luca 15:31 点名补全，详见设计稿 §二B）**——一切角色相对锚点定义，锚点动、全体系动：

```
解析：A=锚点；P=argmin(priority)；gap = priority(A) - priority(P)
判型：gap=0  顶锚型 T —— peak=anchor 退化态（验证不对称物理失效，B-7 知情确认）
     0<gap≤2 常规型 N —— 默认态，零动作（当前 gap=1 即此型）
     gap>2   深降型 D —— 三动作：①确认 anchor ctx ≥ 会话需求 ②关键高峰产出可质询下移给 peak 直接执行 ③矩阵/口诀/profile 仍零改动
断言：ctx(P) ≥ ctx(A)（防 priority 语义反转）；ctx(A) ≥ 常用会话长度（防深研溢出）
```

**动态性四径全覆盖**：
- **锚点上移**（sol→astra，gap→0）：Type-N→T，peak 从真高模退化为 anchor 本体——到达顶部后无处再升，退化须知情（非静默）
- **锚点下移**（sol→luna/5.5/glm，gap 增大）：peak 仍 astra **不变——矩阵、口诀、profile 文件、调用方式全部零改动**；D 型三动作仅是确认清单不是改配置
- **家族顶部换代**（astra→gpt-7）：P 重解析为新顶部，peak.config.toml 的 model 行更新 1 行（SOP-2 唯一维护点）；gap 重算自动改型别
- **新模型入 catalog**：算法只依赖 priority/ctx 两字段，任何新模型写成锚点即自动定型，无配置迁移

**一行自检（已实测，当前输出：anchor=gpt-5.6-sol peak=gpt-6-astra gap=1 → 常规N ✓）**：

```bash
python3 -c "
import json,re; c={m['slug']:m for m in json.load(open('$HOME/.codex/cockpit-model-catalog.json'))['models']}
a=re.search(r'^model\s*=\s*\"([^\"]+)\"',open('$HOME/.codex/config.toml').read()).group(1)
p=min(c,key=lambda s:c[s].get('priority',9999)); g=c[a].get('priority',9999)-c[p]['priority']
print(f'anchor={a} peak={p} gap={g} →', '顶锚T(退化)' if g==0 else '常规N' if g<=2 else '深降D(三动作)')
print('ctx断言(P≥A):', c[p]['context_window']>=c[a]['context_window'], '| anchor ctx:', c[a]['context_window'])"
```
