## 0. 诉求（luca 原话归纳）

OD 产出的交付 HTML 需带交互逻辑说明：

1. 侧边栏写入交互逻辑说明文案；
2. AI 可写、人可改；
3. 每条说明与 HTML 某个功能点/框架区域相关 → badge 锚定（页面元素标 badge「1」↔ 侧边栏「1-交互说明」，1:1）；
4. badge 支持新增、删除、显示/不显示。

隐含约束（会审中确认）：不污染设计本体、能在 OD 迭代周期中存活、单文件自包含交付。

## 2. 最终架构（三层）

```text
数据层   prototype-spec.md 新增「Interaction Notes Index」节 = 概念锚 SSOT
         index.html 内嵌 JSON 块（IA-NOTES 区块）= 投影 + 当前 selector + revision
资产层   office/references/interaction-notes.md = 完整流程与数据契约（共享，零入口零 load）
         注入 runtime（最简无依赖 vanilla JS 内联块，全 inline style）
流程层   open-design SKILL.md Phase 4.5 强指针（唯一挂点）
         by-name 隐藏薄壳（独立入口兜底，不进一级列表）
```

## 3. 挂点（回答「在哪个节点」）

- **主挂点**：open-design **Phase 4（回收落盘）之后、Phase 5（交付）之前**，且仅当「用户已选定方案 mv 成 index.html」且**用户显式点名**要交互说明时注入（不自动跑，守「人工判断后置」既有约束）。
- **注入范围**：仅 index.html（选定方案）。多方案未选中的、导航页一律排除。
- **workflow-graph 表达**：design_output 段加一行注记（「产物可叠 interaction-notes，见 reference，fallback 生成器同享」），**不新增节点/边**——注解是交付后增强，非生成器选择层成员。
- **独立入口**：by-name 隐藏薄壳，供「给任意已落盘 prototype 补交互说明」（magicpath/html-prototype 产物同享）。

## 4. 数据契约

**概念锚（SSOT，存 prototype-spec.md「Interaction Notes Index」节）**：

```yaml
- id: "1"
  concept: "列表筛选联动"        # 语义概念锚：这条说明指的是什么功能点
  title: "筛选即时刷新"
  decisionCardId: "D-003"        # best-effort 回链，可为空；只留在索引层不进下游契约
  note: "点筛选即时刷新列表，不整页跳转"
```

**投影（存 index.html IA-NOTES 区块，`</body>` 前）**：

```html
<!-- IA-NOTES:START (delimiter only; SSOT = prototype-spec.md Interaction Notes Index) -->
<script type="application/json" id="interaction-notes">
{ "revision": 3,
  "items": [ { "id":"1", "concept":"列表筛选联动",
    "anchor": { "selector":"...", "fingerprint":"...", "status":"ok|drifted|invalid" },
    "visible": true } ] }
</script>
<script>/* 注入 runtime：渲染侧栏+badge+全局开关，全 inline style */</script>
<!-- IA-NOTES:END -->
```

工程细则（前端专家意见采纳）：
- JSON 内 `<` 一律转义 `\u003c`（防 `</script>` 提前闭合）；
- 注入前确保 `<meta charset="utf-8">` 存在（file:// 双击中文乱码防护）；
- badge = 运行时 `target.appendChild` + 强制祖先 `position:relative`（滚动/动画下比覆盖层+getBoundingClientRect 稳）；
- M1 样式隔离 = 全 inline style + 大 z-index（零外部 class、不碰 `:root` 变量）；M2 升 shadow DOM。

**SSOT 边界**（红队 V1 终裁）：prototype-spec.md 既有「Design Decision Coverage」答「决策是否被设计体现」；新增「Interaction Notes Index」答「注解锚的语义定义与投影状态」。两节互相一行引用，不重述。HTML 注解 body 只写短说明 + 回链，**不重述设计意图**。

## 5. 锚定机制与生命周期

- **概念锚生命周期三事件**：新增锚 / 修改锚 / 废弃锚——全部过人工确认门，agent 不得自动重生（红队 A1 终裁：predictability）。
- **recover 迭代回收时**（OD 重生成 HTML 后）：agent 读旧投影 + 新 HTML，只做 **selector 重定位 diff**，产出三态清单回显——命中 N / 漂移 M（旧→新 selector，须确认）/ 失效 K（待人工重指）——**未确认不落盘**。概念锚定义本身不动，迭代成本不随 OD 重生成放大（红队 A9a 终裁）。
- 文本指纹与 selector 仅作重定位辅助；运行时失效条目显示警示态（badge 红色边框 + 侧栏失效列表）。
- 设计真改需要改锚定义时：走「修改锚」子流程（diff 回显 + 人工确认），与漂移同门，不留 agent 自动通道。

## 6. 编辑模型（人机分工）

- **主路径（AI 写）**：agent 对话式代改——「把 3 号说明改成…」「给商机推进卡加一条」——agent 同时更新 prototype-spec 索引与 HTML 投影两处（一次事务）。
- **草稿层（人改）**：侧边栏 contenteditable → localStorage 暂存（Safari file:// 下 try-catch 降级 in-memory）；JSON 带 revision，浏览器开页比对草稿 revision 与文件 revision，不一致提示重载；**localStorage 永不作真值**（红队 A4 终裁）。「复制当前注解 JSON」作 escape hatch。
- **badge 增/删**：结构操作走 agent 对话式（M1）；侧栏内直接增删 UI 延 M2。

## 7. 显隐与交付形态

- **默认 ON**（红队 A6 终裁：需求原句即「交付 HTML 带交互逻辑说明」，默认 OFF 直接违背目的）。
- 两级显隐：全局开关（localStorage+UI 为准，`?notes=off` 仅评审快捷）+ 单条 `visible`（单条隐藏=草稿态：badge 与条目不渲染，数据保留）。
- **strip 外发**：一键命令产 `index.clean.html`（同目录固定命名）——剥离 IA-NOTES 区块与 runtime，无决策卡 ID。**带注解 index.html = 唯一真值**：figma-layer / tech-spec / 迭代 recover 恒读它；`index.clean.html` 仅外发，不存在于下游词汇表（红队 V3 终裁；open-design Phase 6 handoff 模板注明）。
- **粒度契约**：一个 badge = 一个「不看说明会误解行为」的交互点（纯视觉不标）；单页 ≤5 为门禁阈值（脚本化，超出报告不标 DONE，仿 FxUI 泄漏检查先例）。
- badge 视觉用注解层自有中性 token（非品牌色，守产品中立 + FxUI 收窄口径「#FF8000 全页≤3处」不冲突）。

## 8. 落地动议（框架只读 → 单一变更包，待 luca 裁决）

框架树内改动打包为一个变更动议，**精确 diff + 版本号升级 + FM-11 验收五判据**，一次性裁决；落地前该行为不可触发（不存在半生效状态）：

| # | 改动 | 类型 |
|---|---|---|
| 1 | `open-design/SKILL.md` 加 Phase 4.5 强指针：「用户点名要交互说明/badge 时，必须先读 `office/references/interaction-notes.md` 到 FILE_END 再动手」；Phase 5 加一句独立入口提示；Phase 6 handoff 模板加注解状态字段 + strip 命名约定；版本号 +0.1 | 修改 |
| 2 | 新建 `office/references/interaction-notes.md`（完整流程 + 数据契约 + 注入/重锚定/strip 脚本 + 门禁规则） | 新增 |
| 3 | 新建 by-name 隐藏薄壳 skill（description 含自然触发词：「给 HTML 加交互说明 / badge / 标注交互逻辑」） | 新增 |
| 4 | `CLAUDE.md` 隐藏 skill 表登记薄壳（消费面兜底） | 修改 |
| 5 | `optional-workflow-graph.yaml` design_output 段加一行注记 | 修改 |

**FM-11 验收判据（五条全绿才过，任何一条红 → 回改再测，不允许盲批）**（红队 V4 终裁）：

1. 可达性：新会话说「给这个原型加交互说明/badge」路由命中薄壳/reference，3/3 次；
2. 注入烟测：对真实 OD 产物注入后，文件本体除 IA-NOTES 区块与 runtime script 标签外零 diff（diff 校验）；浏览器打开侧栏+badge 渲染正常、全局开关可用；
3. 样式红绿灯：注入后宿主页面布局零位移（视觉对比）+ 侧栏自身可读；红 → 升 M2 shadow DOM；
4. recover 迁移烟测：模拟 OD 重生成（改若干 class），三态清单输出正确、人工确认门生效（未确认不落盘）；
5. 门禁生效：badge >5 时拒标 DONE。

## 9. MVP 分期

- **M1**：prototype-spec「Interaction Notes Index」节 + agent 注入固定格式说明区块（最简 vanilla JS：侧栏 + badge + 全局开关，全 inline style）+ agent 对话式代改 + recover 重定位 diff + 人工确认门 + badge≤5 门禁 + strip 命令。
- **M2**：浏览器 contenteditable 草稿层（revision 比对）/ 侧栏内增删 UI / 指纹辅助重定位 / shadow DOM 隔离 / 精细视觉。

## 10. 未决项（仅参数级，无架构级未决）

- 单页 badge 上限 5 是否按页面密度调（3-8 区间）。
