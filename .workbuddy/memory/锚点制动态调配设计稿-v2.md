## 一、峰值三明治（核心模式，多峰循环）

```
计划(peak) → 执行(anchor) → 验证(peak) ⟲（验证否决 → 重规划(peak) → 再执行 → 再验证）
```

luca 原话锚点："开始计划和结果验证需要高模型"。**这不是单 pass 三明治，是多峰循环**——每次循环回跳都重新进入 peak。

它正是本仓 fable_whitelist P0/P1/P2（出门前裁决/对抗判定/复审与规划）在 Codex 侧的缺失投影——v1.3 报告 F3 所述缺口，本设计 = F3 的修复动议（模型版）。

**退化态诚实声明（红队 R1-1）**：anchor=家族顶部时峰值退化（peak=anchor），验证不对称原则（判官≥执行者）物理失效——判官=执行者。这不是"可接受的退化"而是"必须知晓的失效"，已入 B-7。异构判官（跨家族模型互验，可规避同源盲区）是理论逃逸通道，但 luca 未钦定、catalog 外家族模型（glm/grok/deepseek）能力未经评估——记录在案不启用。

## 二、两角色制（模型第一公民，无 effort 轴）

| 角色 | 解析规则 | 当前实例 | 说明 |
|---|---|---|---|
| **anchor** | config 顶层 `model =` 行（luca 随时改，唯一 truth） | gpt-5.6-sol | 承担一切执行场景；同时是质量地板（token 夯够、质量优先，不向下换模型） |
| **peak** | catalog `priority` 最小值（家族顶部），规则解析而非写死 | gpt-6-astra (priority=0) | 红队/会审/计划/验证/长上下文/compact 摘要 |

## 二B、锚点动态兼容方案（Anchor-Relative Resolution，ARR）

**核心机制：一切角色相对锚点定义，锚点动、全体系动；全配置零硬编码锚点名。**

### 2B.1 解析算法（伪代码，任何锚点代入即得确定输出）

```
输入：anchor_slug = config 顶层 model 行（动态，luca 主权）
     catalog = ~/.codex/cockpit-model-catalog.json（或 codex debug models）

第 1 步 定锚     A = anchor_slug
第 2 步 定顶     P = argmin(catalog.priority)          # 家族顶部（当前 gpt-6-astra）
第 3 步 定差     gap = priority(A) - priority(P)        # ≥0；0=锚点即顶部
第 4 步 判型     gap = 0        → 顶锚型（Type-T）
                 0 < gap ≤ G    → 常规型（Type-N）       # G=正常代差阈值，建议 2
                 gap > G        → 深降型（Type-D）       # 锚点大幅低于顶部（跨代/外家族）
第 5 步 出角色   peak   = P（Type-T 时 peak=anchor，见退化声明）
                 anchor = A（不变；anchor 同时是质量地板，向下不换模型）
第 6 步 断言     ctx(P) ≥ ctx(A)（否则 priority 语义反转，告警停）
                 ctx(A) ≥ 常用会话长度（深研/长会话防溢出）
```

### 2B.2 三型五径全覆盖表（向上向下兼容的完备输出）

| 锚点位置（例） | gap | 型 | peak 行为 | anchor 行为 | 额外动作 |
|---|---|---|---|---|---|
| gpt-6-astra（=顶） | 0 | **顶锚型 T** | peak=anchor（退化：验证不对称物理失效，B-7 知情确认） | astra 本体 | SOP 步骤 1 显式确认退化态；红队/会审照常 `--profile peak`（等价 anchor） |
| gpt-5.6-sol（当前） | 1 | **常规型 N** | astra | sol | 无（默认态，零动作） |
| gpt-5.6-terra / luna | 2-3 | **常规型 N**（gap≤G=2）或**深降型 D**（gap>2） | astra | terra/luna | N：无动作；D：见下 |
| gpt-5.5 / gpt-5.4 | 6-15 | **深降型 D** | astra | 5.5/5.4 | D 型三动作：①确认 anchor ctx（272k）≥ 会话需求 ②高峰场景（红队/终裁）若嫌 anchor 质量不足→可用 peak 直接执行关键产出（质询锚点下移）③矩阵/口诀零改动 |
| glm-5.3 / grok-4.6（外家族） | ~1000 | **深降型 D**（极端） | astra | 外家族模型 | 同 D 三动作 + B-9（外家族 anchor 时 peak 升 astra 的"升档幅度"跨家族，质量假设需 luca 亲自试用评估） |

### 2B.3 动态性声明（luca"默认模型也会变更"的正面回答）

- **锚点上移**（sol→astra，gap 1→0）：Type-N → Type-T，peak 从"真高模"退化为 anchor 本体——这是向上兼容的代价：**到达顶部后无处再升**，不对称由"跨模型"退为"同模型高强度"（B-7 知情确认，非静默）
- **锚点下移**（sol→luna，gap 1→3）：Type-N → Type-D，peak 仍 astra 不变——**矩阵、口诀、profile 文件、调用方式全部零改动**；D 型三动作仅是"确认清单"不是"改配置"
- **家族顶部换代**（astra→gpt-7）：P 重解析为新顶部，peak.config.toml 的 model 行更新 1 行（SOP-2，唯一维护点）；gap 重算可能改变型别——体系自动适应
- **新锚点入 catalog 即被识别**：算法只依赖 priority/ctx 两字段，luca 把任何新模型写成锚点，第 2 天体系自动给它定型、无任何配置迁移

### 2B.4 与 §五 SOP 的关系

ARR 是 SOP 步骤 1/2 的**决策内核**：SOP 是操作清单（何时跑），ARR 是判定逻辑（跑出什么结论、该做什么）。SOP-1 的"向下分支校验 ctx / 向上分支确认退化"就是 ARR 第 4/6 步的清单化。

### 2B.5 一行自检（ARR 快速判型，可手动可脚本化）

```bash
python3 -c "
import json; c={m['slug']:m for m in json.load(open('$HOME/.codex/cockpit-model-catalog.json'))['models']}
import re
a=re.search(r'^model\s*=\s*\"([^\"]+)\"',open('$HOME/.codex/config.toml').read()).group(1)
p=min(c,key=lambda s:c[s].get('priority',9999))
g=c[a].get('priority',9999)-c[p]['priority']
print(f'anchor={a}(p{c[a][\"priority\"]}) peak={p}(p{c[p][\"priority\"]}) gap={g} → '+('顶锚T(退化,B-7)' if g==0 else '常规N' if g<=2 else '深降D(三动作)'))
print(f'ctx: anchor={c[a][\"context_window\"]} peak={c[p][\"context_window\"]}  断言ctx(P)≥ctx(A):', c[p]['context_window']>=c[a]['context_window'])"
```

**场景 8 降级说明（红队 R1-2 命中）**：原"深研中的抉择/收敛时刻→peak"无操作定义（"抉择"判定标准模糊，agent 在任务流中无法自判），且是 11 场景中唯一需 agent 任务流内自判切换的——判定者既无合同又无标准，等于死条款。**降级为指引**：深研产出计划的前置输入且输入质量存疑时，由人（luca）显式把该抉择环节交给 peak 处理——是人的显式判断，不是 agent 自主切换。矩阵中不再是独立场景。

**判定口诀（agent 行为合同）**：*规划与裁决升 peak，执行与深研守 anchor；不可逆前与压缩前，同样是 peak。*

**验证不对称核验**：peak 审 anchor 产物（正向不对称，正确）；anchor 执行 peak 计划（合法——执行者弱于规划者）；anchor review peak 产物（口诀反向排除——裁决必 peak）。退化态下三向全部失效（B-7）。

## 四、载体与调用规范（P0 修正版，codex-cli 0.154.0 实测）

**正确机制：独立 profile 文件**

```toml
# 新建 ~/.codex/peak.config.toml —— 全部内容：
model = "gpt-6-astra"        # = catalog priority 最小值；家族换代按 SOP §五 重解析
# 省略 model 行则继承 config.toml 顶层锚点（实测确认）；
# peak 必须显式写——"向上一格"的物理载体
# effort 行：不写（见下"effort 显式决策"）
```

- **对 config.toml 零改动**（662 行原样，锚点行保持 luca 主权）
- **废弃声明**：内嵌 `[profiles.peak]` 写法作废——0.154.0 实测报错：`--profile 'peak' cannot be used while config.toml contains legacy profile config; move those settings into .../peak.config.toml`

**调用规范（红队 R1-6 修正：--profile 优先，-m 禁入日常推荐）**：
- 会话切换：`codex --profile peak`
- 一次性：`codex exec --profile peak "..."`
- **agent spawn 统一 `--profile peak`**——**不推荐 `-m <模型名>` 直传**（R1-6 命中：每个 -m 点都是硬编码模型名，peak 换代后所有 spawn 点静默指向旧模型且无检测器——N 个分散断点比 1 个集中 profile 文件更糟，与 F10 同罪且更分散）
- **免费冒烟**：exec banner 首屏打印 `model:` 行——grep 断言 fail-loud

**effort 显式决策（红队 R1-5 修正）**：peak.config.toml **不写 effort 行**。实测语义：不写 → 继承 config 顶层 `model_reasoning_effort = "xhigh"`（这不是"正交无矛盾"，是**静默耦合**——luca 改全局 effort 会联动 peak）。本设计不设 effort 轴（luca 钦定），因此把继承现状如实声明为已知耦合（B-8），不做任何 effort 决策。若 luca 未来想隔离，在 peak.config.toml 加一行 `model_reasoning_effort = "<值>"` 即切断——单行开关，留给主权决策。
